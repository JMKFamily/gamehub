## 2. 콤보

### 2-1. 증가와 끊김

| 항목 | 내용 | 확정도·출처 |
|---|---|---|
| 증가 단위 | 성공한 노트 1개 = +1 (가장 낮은 성공 포함). 롱노트는 중간 틱마다 추가 | [위키] S2, [문서] S5 |
| 피버 중 | 피버 배율만큼 노트당 콤보가 더 오름(최대 노트당 5배) | [커뮤니티] S8·S9 |
| 끊김 | 노트를 놓치면(실패 등급) 콤보가 **0으로** 돌아가고 다음 성공부터 다시 1 | [문서] S5·S6 |
| 곡 중단과 콤보 | 놓친 뒤 곡을 나가면 쌓인 콤보 기록이 사라짐(업적 맥락) | [커뮤니티] S8 |
| 콤보 유지 설정 | 1.08 버전에서 자유 모드용 "콤보 유지" 켜기/끄기 추가(곡 사이 이어 가기) | [위키] S2 |
| 실패해도 곡은 계속 | 보통·어려움 난이도는 게임 오버 없이 끝까지 감(이후 패치), 최고 난이도에서만 게임 오버 | [커뮤니티] S11, [위키] S2 |

핵심 구조: **원작에서는 "콤보 끊김"과 "곡 실패"가 다른 사건**입니다. 놓쳐도 곡은 계속되고 콤보만 0이 됩니다. 우리 세 게임은 반대로 **한 번 놓치면 그 시도가 실패하고 1.1 s 뒤 처음부터** 다시 합니다(runner-01 사망, rhythm-01·02 놓침). 그래서 우리 게임에서 콤보 끊김은 **늘 실패·재시작과 같은 순간**이고, "끝까지 콤보 유지 = 클리어"입니다. 4절 권장안은 이 차이에서 출발합니다.

### 2-2. 화면 표시와 시간 구조

공개 자료에 ms 단위 연출 수치는 없습니다. 아래는 리듬 게임 판정 표시의 일반 구조를 정리한 것이고, **모두 [추정]**입니다(실측 요청 시 영상 프레임 측정 가능).

| 순서 | 내용 | 시간 (추정) |
|---|---|---|
| ① 누름 순간 | 레인(입력칸) 빛 + 키음(2-4) | 입력 프레임 |
| ② 판정 | 판정선 위치에서 등급 글자가 나타남. 커졌다 줄어드는 짧은 튐 | 같은 프레임 시작, 튐 약 0.05~0.1 s |
| ③ 콤보 갱신 | 레인 가운데 위쪽, 판정 글자 가까이에 큰 숫자. 숫자가 바뀔 때 살짝 튐 | 판정과 같은 프레임 |
| ④ 유지·사라짐 | 다음 판정이 오면 즉시 덮어씀. 판정이 없으면 수백 ms 뒤 흐려짐 | 약 0.3~0.5 s |
| ⑤ 끊김 | 콤보 숫자가 사라지고 실패 등급 글자가 같은 자리에 뜸 | 실패 프레임 |

- 위치 원리: 판정·콤보는 **시선이 가 있는 곳(노트가 떨어지는 판정선 바로 위, 화면 가운데 줄)**에 둡니다. 눈을 옮기지 않고 결과를 봅니다.
- 판정 글자와 콤보 숫자의 위치·모양·이르고 늦음 표시·평균 판정률은 사용자가 HUD 설정에서 옮기거나 끌 수 있습니다 [공식] S7. 즉 **판정 표시는 숙련자에게 "꺼도 되는 정보"**로 다뤄집니다.

### 2-4. 즉시 피드백 구조 (키음)

| 항목 | 내용 | 확정도·출처 |
|---|---|---|
| 키음 | 노트를 맞게 치면 곡에서 빠져 있던 악기 소리가 채워짐. 놓치면 그 소리가 비어 들림 | [문서] S5 |
| 피드백 순서 | 소리(키음) → 그림(레인 빛·히트 이펙트·판정 글자) → 숫자(콤보)가 **모두 같은 입력 프레임에 시작** | [추정] |
| 이른·늦은 소리 | 키음은 누른 순간 나므로 이르게 치면 이르게 들림(판정 등급과 별개로 귀가 오차를 알려 줌) | [추정] |

우리 rhythm-01·rhythm-02는 이미 같은 구조입니다("판정 별 자리의 타악은 곡에서 빼고 아이 탭 소리로 냄", "북 자리는 비어 있고 아이 탭이 채운다"). runner-01은 레퍼런스(Geometry Dash)대로 점프 소리가 없습니다(insights 레퍼런스 감각 4번째 줄).

## 3. 피드백을 5~6세에게 옮길 때 남길 구조

1. **같은 프레임**: 판정 반응(그림·소리)과 콤보 갱신은 입력 프레임(늦게 친 통과는 판정 프레임)에 시작합니다. 기존 기준 "입력 후 1프레임 안 판정 이펙트"(criteria 게임 감각 rhythm-01 해석 줄)와 같습니다.
2. **시선 위치**: 콤보 표시는 판정 대상 가까이 두되 **판정 대상·다음 노트의 위험 구간을 가리지 않습니다**.
3. **소리가 첫 피드백**: 성공 소리 층이 등급을 알려 주고, 그림은 보조입니다(글 없이도 귀로 앎).
4. **끄기 쉬운 정보**: 콤보는 플레이에 필요 없는 정보입니다. 지워도 게임이 그대로 성립해야 합니다(아트 컨셉 약하게 원칙과 같은 시험).

## 4. 5~6세용 변환안 (공통 권장값)

### 4-1. 등급: 3개 이하, 기존 판정 창 그대로

| 우리 등급(기존 이름) | 원작 대응(구조만) | 판정 폭 권장 | 구분 (글 없음) |
|---|---|---|---|
| 1단 (rhythm: 딱) | 최고 등급 | **±50 ms** (원작 보통 판정 최고 등급 ±41.67 [커뮤니티]보다 약 20 % 너그러움) | 가장 큰 반응 + 소리 층 가장 많음 + 전용 색 짧게 |
| 2단 (rhythm: 좋아) | 중간 등급 | **±100 ms (L4부터 ±90)** | 중간 반응 + 소리 층 1개 적음 |
| 3단 (rhythm: 통과) | 가장 낮은 성공(콤보 유지) | 통과 창 나머지 전부 | 작은 반응 + 기본 탭 소리만 |
| 실패 | 실패 등급 | 통과 창 밖 / 놓침 구역 | 기존 실패 연출 그대로(새 연출 없음) |

- **판정 폭은 새로 정하지 않습니다.** rhythm-01·rhythm-02는 이미 위 3단(±50 / ±100·±90 / 통과)과 모양·소리 구분이 있습니다. 콤보를 붙여도 `judgeAttempt` 결과(클리어·실패 위치·이유)는 한 탭도 바뀌지 않아야 합니다.
- 실패 경계(통과 창)는 각 게임의 아동 기준(σ70 첫 클리어 30회 한도, L1 통과 폭 320 ms 등)으로 이미 원작보다 훨씬 넓습니다. 원작 실패 경계는 공개 수치가 없어 비교하지 않습니다.
- 등급 이름을 화면에 쓰지 않습니다. 구분은 **모양(크기·개수) + 소리 층 수**가 주이고 색은 보조입니다(흑백에서도 구분, rhythm-02 30-art 6절 방식).
- 이르고 늦음(FAST/SLOW 계열) 표시는 넣지 않습니다. 아이에게 신호가 하나 더 생기고, 지연 보정은 보호자 보정 흐름이 맡습니다.

### 4-2. 콤보 규칙

| 규칙 | 권장 | 이유 |
|---|---|---|
| 증가 | 판정 대상 성공 1개 = +1. **3단(통과)도 +1** | 원작도 가장 낮은 성공은 콤보 유지. 아이는 "맞혔다"만으로 늘어나야 함 |
| 세지 않는 것 | 헛탭·무시된 탭(콤보 그대로, 벌 없음), 판정 없는 사건(자동 토스·착지·보여 주기 마디·점프 발판) | 빈 누름으로 콤보가 깨지지 않는 원작 구조 [추정]과 같고, 새 실패 규칙을 만들지 않음 |
| 롱노트 틱 | 해당 없음(세 게임 모두 홀드 없음). 두 공(rhythm-02)은 공마다 접촉 1개 = +1 | |
| 끊김 | **실패 = 끊김 하나뿐**. 실패하면 시도가 끝나므로 다음 시도는 0에서 시작 | 우리 코어는 한 번 놓치면 실패(2-1 끝 단락) |
| 연습 모드 | 체크포인트 부활도 새 시도와 같게 0부터 | 단순함. 최고 콤보 기록은 일반 모드만(진행도와 같은 원칙) |
| 상태 | 콤보 = 이번 시도에서 지금까지 성공한 판정 수(`result.grades.length`와 같은 값). **별도 상태·난수 없음** | 빌드 판정 = 시뮬레이터 판정 불일치 0 기준을 그대로 지킴 |
| 대안(채택 비권장) | "좋아 이상만 콤보, 통과는 콤보 0으로" | 실패 없이 콤보가 끊기는 원작 느낌이 생기지만, 아이에게는 "살았는데 벌 받음" = 새 규칙. 넣을지 각 팀 balance가 정함 |

- 결과적으로 **끝까지 콤보 = 클리어**입니다. 콤보는 클리어 조건·실패 규칙·등급 규칙(작은 북·등급 구름 1~3개)·판정 창·레벨 데이터를 바꾸지 않는 **보상 층**입니다. σ70 첫 클리어 30회 한도와 레벨 10 목표(외삽 ±20 %)는 콤보 전후로 같은 값이어야 합니다(봇 재실행으로 확인, 값이 1이라도 바뀌면 구현 오류).
- 점수·피버·라이프 게이지는 가져오지 않습니다. 피버는 게이지 + 배율이라는 규칙을 두 개 더 만들고, 라이프는 실패 규칙을 바꿉니다.

### 4-3. 콤보 표시 (숫자를 읽지 못해도 보이게)

| 항목 | 권장 |
|---|---|
| 기본 모양 | **작은 점 10칸 줄**: 성공마다 한 칸 참. 10칸이 차면 줄 옆에 **큰 표지 1개**가 생기고 점 줄은 비움(십의 자리 = 큰 표지 수, 일의 자리 = 점 수). 글·숫자 없이 "얼마나 이어 쳤나"가 보임 |
| 숫자 | 기본은 넣지 않음. rhythm-02 HUD는 "글·숫자 없음"이 이미 규칙. runner-01은 HUD에 % 숫자가 있어 보조 숫자를 둘지 art가 정함 |
| 나타나는 시점 | 콤보 2부터(1은 판정 반응만으로 충분) [추정] |
| 위치 | 판정 대상과 가까운 고정 자리, 단 판정 대상·다음 노트의 위험 구간(놓침 구역 ~ 통과 창 끝)·튜토리얼 자리와 겹치지 않음. 4해상도에서 겹침 검사(insights 시각·사운드 rhythm-02 줄) |
| 갱신 연출 | 판정 프레임에 칸이 차며 그 칸만 1.0 → 1.15 → 1.0배, **120 ms**. 가장 짧은 노트 간격(현재 rhythm-01 L10 214 ms, rhythm-02 L10 246 ms. runner-01은 검증기 탭 목록으로 레벨마다 확인)보다 짧아 다음 판정과 겹치지 않음 |
| 번쩍임·흔들림 | 없음(세 게임 공통 금지 규칙) |

### 4-4. 콤보 단계 보상

| 단계 | 연출 권장 | 시간 | 소리 |
|---|---|---|---|
| 5 | 점 줄 5칸째가 조금 더 크게 튐(작은 칭찬) | 120 ms(일반 갱신과 같은 길이) | 없음 또는 성공 소리 층 +1 |
| **10** | 큰 표지 1개가 생김: 점 10개가 모여 표지로 빨려 들어감 | **0.4 s** | 부드러운 화음 한 번, **아이 탭 소리보다 1 dB 이상 작게**(criteria 시각·사운드 "아이 탭이 가장 큰 소리") |
| **20** | 큰 표지 2개째 + 바탕에 아주 작은 색 조각 몇 개가 HUD 띠 안에서 내려옴 | 0.6 s | 10보다 음 하나 높은 화음 |
| 30 | 큰 표지 3개째(같은 규칙) | 0.6 s | 20과 같은 형식 |
| 클리어 | 기존 클리어 연출에 큰 표지·점이 합쳐짐(새 결과 화면 없음) | 기존 클리어 시간축 안 | 기존 |

- 현재 데이터의 판정 수: runner-01 레벨당 필수 탭 15~27, rhythm-01 별 20~29, rhythm-02 접촉 18~26. **30 콤보는 지금 어느 레벨에서도 나오지 않습니다.** 10·20이 실제 단계이고, 30은 레벨이 길어질 때를 위한 자리입니다. 레벨 1(15~20개)에서도 10은 꼭 한 번 볼 수 있습니다.
- 단계 연출은 **HUD 띠 또는 콤보 표시 자리 안에서만** 움직이고 판정 대상·궤도·공 경로 위에 그리지 않습니다. 다음 노트까지 남은 시간보다 길어도 되지만, 그동안 다음 노트의 위험 구간을 가리면 안 됩니다.
- 단계 소리는 성공 탭 소리와 **같은 순간에 겹치지 않게** 다음 정박(또는 0.5박 뒤)에 냅니다 [추정]. 탭 직후 바로 겹치면 등급 소리 층 수를 헷갈립니다.
- 최고 콤보 기록: 레벨 선택 카드에 큰 표지 수만큼 작은 표지(글·숫자 없음)를 둘 수 있습니다(선택). 등급 표시와 모양이 겹치지 않게 art가 정합니다.

### 4-5. 끊김 연출 (겁주지 않기)

| 금지 | 권장 |
|---|---|
| 빨간 ✕, 깨지는 숫자, 경고음, 화면 흔들림, "0" 크게 띄우기, 잃은 개수 보여 주기 | 기존 실패 연출 0.3 s 안에 점 줄·큰 표지가 **조용히 작아지며 사라짐**(소리 없음). 1.1 s 재시작 뒤 빈 줄로 시작 |

## 5. 프로젝트별 적용 메모

### 5-1. runner-01 Reverbound (원버튼 리듬 러너)

**지금 구조.** 판정은 물리입니다(`games/reverbound/js/physics.js` `step()`, 240 Hz). 탭은 "접지 중이면 점프"일 뿐 등급이 없고, 살고 죽는 것만 있습니다(`game.js` `onDeath`/`onClear`). 그러나 레벨은 **모든 필수 탭이 정박(반박)에 오도록 역산**돼 있고(20-balance 1절 3번), 검증기 `tools/verify-levels.mjs`가 탭마다 타이밍 창을 계산합니다. 레벨 1 예: 탭 15회, 박 탭 기준 창 −129.2 / +133.3 ms(266.7 ms), 낮은 장애물 300 ms. 10레벨 전체: 필수 탭 15~27회(공중 재점프 포함), 최소 창 170.8 ms(2연속, 박 기준 약 ±85).

**붙이는 곳.** "노트" = 검증기가 찾은 필수 탭(공중 재점프 탭 포함, 점프 발판 자동 점프 제외). 탭 시각과 그 탭의 **설계 박 시각** 차이 e로 등급을 줍니다: |e| ≤ 50 → 1단, ≤ 100 → 2단, 그 밖이지만 창 안 → 3단(창이 ±85인 곳은 2단이 창 끝에서 잘려 사실상 2단계). 생사는 지금처럼 물리만 정하고 등급은 표시용입니다. 맞출 탭이 없는 점프(빈 곳 점프)는 무시합니다. 콤보는 등급이 붙은 탭마다 +1, 사망하면 0. 이를 위해 레벨 데이터에 탭 목록(박, 창 앞뒤 ms)이 필요하고, 빌드는 그 목록과 입력 틱을 짝짓기만 합니다(물리·검증 결과 불변). 판정 반응은 **플레이어 기준 위치**(insights 5~6세 줄)에 그리고, 레퍼런스에 점프 소리가 없으므로 등급 소리를 넣을지는 art가 정합니다(넣는다면 곡의 빈 타악 자리를 채우는 키음식, 2-4). 콤보 줄은 위쪽 진행도 바 근처 HUD에 둡니다.

- balance: 레벨별 판정 탭 목록(`build-levels.mjs`/검증기 산출을 레벨 JSON에), 등급 폭·콤보 단계 키를 `balance.json`에. 봇 지표 불변 확인
- dev: 입력 틱 ↔ 판정 탭 짝짓기(가장 가까운 안 쓴 탭, 그 창 안일 때만), 등급 반응·콤보 HUD, 사망 시 0, 테스트 훅에 콤보 값 노출, 게임 시계 기준 연출(insights 구현 줄)
- art: 3단 반응 모양(플레이어 주변, 위험 요소 위 금지), 점 줄·큰 표지, 단계 연출, 소리 여부·크기 순서(오프라인 렌더)
- lore: 대체 글(콤보 단계 `aria-valuenow` 방식, 플레이 중 문구 추가 없음)
- qa: 콤보 전후 봇 결과 동일, 판정 반응 1프레임, 4해상도 겹침

### 5-2. rhythm-01 Tickadrum (원버튼 리듬, 원형 궤도)

**지금 구조.** `games/rhythm-01/js/judge.js` `judgeAttempt`가 아직 안 친 가장 이른 별 하나만 보고 딱(±50)/좋아(±100, L4부터 ±90)/통과(−150 ~ +170 등 레벨별)로 나누며, 놓침 구역 탭은 "너무 일찍" 실패, 창 끝까지 없으면 "놓침" 실패입니다(20-balance 4·5절). 탭 처리는 `main.js gameTap()` → `engine.js tap(V)`가 `r.kind`(perfect/good/pass/stray)를 돌려주고, 등급별 소리(딱 = 탭 + 높은 종, 좋아 = 탭 + 낮은 종, 통과 = 통과 탭 소리)와 빛살(8 / 4 / 0개, 별 크기 1.45 / 1.25 / 0.35배)이 이미 3단으로 다릅니다(30-art 7절). 레벨당 판정 별 20~29개, 최소 간격 214 ms(L10).

**붙이는 곳.** 등급은 이미 요구(3단, 글 없음)를 만족하므로 바꿀 것이 없습니다. 콤보는 `tap(V)`가 perfect/good/pass를 돌려준 순간 +1, 실패 사건에서 0이면 됩니다(= 시도 안 `grades` 길이). 보여 주기 마디의 탭·헛탭(`stray`)은 세지 않습니다. 화면 자리는 가운데 북(둥둥이) 둘레 안쪽이 시선과 가깝지만, 북은 탭마다 물결 고리가 나는 자리라 신호가 겹칠 수 있습니다. 궤도 바깥 HUD(진행도 막대 아래·시도 점 옆) 쪽이 안전합니다. 노랑(`star`)은 별·빛살 전용이므로 콤보 표시에 쓰지 않습니다. 단계 연출은 다음 마디 별이 커지며 나타나는 시각(`preview.grow_start`)·북채 창과 겹치지 않는지 검증기 S15·S16과 같은 방식으로 시간축 검사를 추가하면 좋습니다.

- balance: 콤보 규칙·단계 키(`balance.json`), 시간축 겹침 검사 추가 여부, 봇 결과 불변 확인
- art: 콤보 자리(4해상도), 점 줄·큰 표지 모양·색(노랑 금지), 단계 화음 크기(탭보다 1 dB 이상 작게, 오프라인 렌더)
- dev: `engine.js`에서 콤보 파생, 실패 연출 안 사라짐, aria 값
- lore: 대체 글 키(값은 `aria-valuenow`, R8 규칙)

### 5-3. rhythm-02 Tossaloft 높이통통 (공이 북에 닿을 때 탭)

**지금 구조.** `games/rhythm-02/js/judge.js` `judgeAttempt`가 rhythm-01과 같은 순서로 접촉을 판정합니다. 딱 ±50 / 좋아 ±100(L4부터 ±90) / 통과(L1 −150 ~ +170 … L10 −115 ~ +135), 놓침 구역 200 ms(20-balance 4-1). 판정 반응은 "튐 선" 2 / 1 / 0쌍 + 북 가죽 납작 0.75 / 0.85 + 딱일 때만 glow 0.15 s, 소리는 북 + 높은 종 / 낮은 종(30-art 6절), 이미 글 없이 3단입니다. 자동 토스·착지·받침 쉼은 판정 없음. 레벨당 접촉 18~26개, 최소 간격 246 ms(L10). HUD는 "글·숫자 없음, 진행도 막대 + 시도 점 + 멈춤 버튼"(30-art 4-4).

**붙이는 곳.** 콤보는 접촉 성공(`grades.push`)마다 +1, 실패 시 0. 두 공 구절도 접촉마다 +1(공 구분 없음). 받침 쉼의 탭(북만 톡)은 세지 않습니다. 화면 자리는 HUD 띠 안(진행도 막대 아래)을 권하고, 구름·공 최대 꼭짓점·`text_slots`와 겹침을 4해상도 × 가장 긴 언어로 검사합니다(insights rhythm-02 시각 줄). 이 게임은 받침 쉼이 구절마다 있어 **단계 연출을 받침 쉼 첫 박으로 미뤄** 보여 줄 수 있습니다(위험 구간 밖, 공이 앉아 있는 시간). 바탕 단계(받침 쉼 n번째 = min(n, 3)단계)는 이미 "진행하면 바뀌는 보상"이므로 콤보 단계와 다른 모양으로 둬 두 신호가 같은 뜻으로 읽히지 않게 합니다(신호 수 insights).

- balance: 콤보 키, 단계 연출을 받침 쉼으로 미룰지, 봇 불변 확인
- art: HUD 띠 안 점 줄·표지(공 색 `ball`은 공·최고 기록 전용이라 쓰지 않음), 단계 화음, 겹침 검사 대상에 콤보 자리 추가
- dev: `core.js` 시도 판정에서 콤보 파생, 실패 연출 0.3 s 안 사라짐, 테스트 훅
- lore: 대체 글 키, 접근성 트리로 확인(insights rhythm-02 줄)

### 5-4. 세 게임 공통 확인 항목 (qa·리뷰 제안)

1. 콤보를 켠 빌드와 끈 빌드의 봇 재판정 결과(클리어·실패 위치·이유) 불일치 0, σ70 첫 클리어 중앙값·L10 목표 값 동일
2. 판정 반응·콤보 갱신이 입력(늦은 통과는 판정) 후 1프레임 안에 시작
3. 콤보 표시·단계 연출이 4해상도에서 판정 대상·위험 구간·튜토리얼·HUD 버튼과 겹치지 않음
4. 단계 화음이 아이 탭 소리보다 1 dB 이상 작음(오프라인 렌더)
5. 실패 → 다음 시도 첫 프레임 시간이 콤보 전과 같음
6. 글을 지운 화면(notext)에서 콤보 단계가 구분됨(점 수·표지 수)

## 6. 남은 불확실성

- 원작 최고 등급 폭(±41.67 vs ±20.8 ms), 실패 경계, 롱노트 틱 간격, 피버 중 실패 규칙, 판정·콤보 표시의 ms 연출은 공개 자료로 확정하지 못했습니다. 우리 권장값은 이 값들에 기대지 않게(각 게임의 기존 판정 창을 그대로 쓰게) 짰습니다.
- 표시 시간 구조(2-2)를 원작과 맞추고 싶으면 공개 플레이 영상의 프레임 측정이 필요합니다(`harness/guides/hands-on-benchmark.md`, 요청 시).
- 점 10칸 + 큰 표지 방식이 5~6세에게 "숫자 대신"으로 읽히는지는 아동 테스트로만 확인됩니다.
