## 요청 받은 일
오케스트레이터(요청자 지시 2026-11-17 전달): Flow Free 의 규칙·조작·진행 구조를 벤치마크하되 레벨 배치는 재현하지 않고 **자체 생성기 + 답이 하나뿐인 판**으로 10레벨, 5~6세 단순 규칙, criteria 밸런스 절 난이도 압축 규칙을 퍼즐에 맞게 해석, 콤보·판정 이름·% 를 퍼즐에 적용할지 판단. 빌드·봇·검증기가 같이 쓰는 판정 모듈과 node 도구, `balance.json`, `levels/`, `20-balance.md`, 이 보고서.

## 한 일
1. 판정 모듈 `tools/core/board.mjs`(ES 모듈, 의존 0, 브라우저 import 가능): 누름(점 0.25칸 확장)·칸 추적(히스테리시스 20 %)·드래그(첫 칸 이동에 지움, 자르기·같은 드래그 안 되살림, 다른 색 점 막힘, 짝 점 도달 뒤 멈춤, 건너뛴 칸 채움)·뗌·되돌리기·처음부터·이동 수(00-benchmark 13-2 정의)·완료(연결 프레임 판정 + 잠금)·표시층(쌍 점 줄·채움 %·등급·결과 %·별).
2. 생성기 `tools/gen/generate.mjs`(답 먼저: 무작위 걸음 덮개 → 합치기·자르기 → 거르기 F1~F3, 시드 결정적) + 유일해 검증기 `tools/gen/solve.mjs`(sound/none/trap 세 모드, 답 2개에서 멈춤).
3. 함정 실측 `tools/trap-check.mjs`: 생성용 "자기 선 이웃 금지"를 검증기에 넣으면 유일하지 않은 판을 유일로 통과시키는 것을 수로 확인(아래 검증 결과).
4. 봇 `tools/sim/bots.mjs`: 5~6세 대리(CHILD, 답 모름, 00-benchmark 14-4 모델) · 숙련(SKILLED, 머릿속 국소 모순 검사) · 중간(MID). 시드 인자, `mixSeed` 로 레벨·실행·시드별 독립 난수.
5. 탐색 도구: `search-levels.mjs`(자리별 후보 수천 판 + 짧은 봇 실행) → `pick-levels.mjs`·`conc-screen.mjs`(목표 곡선·몰림) → `levels-picks.json` → `build-levels.mjs`(levels/*.json 재생성). 자리 설정 `levels-config.mjs`.
6. `verify-levels.mjs`: 규칙 단위 R1~R11, 레벨 V0~V8, 곡선 B0~B7, 표시층 C1·C2, 몰림 K1, 함정 정보 T1. **ALL PASS**.
7. `balance.json`, `levels/01-level1.json … 10-level10.json`, `20-balance.md`(해석 표·결정안·레벨 표·스키마·튜토리얼).
8. 병렬로 나온 30-art·10-lore 를 읽고 겹치는 수치(튜토리얼 시간, 등급별 튐·조각 수, 판정 이름 자리)를 balance.json 에 맞춤. 레벨 `name_key` 를 lore 키 `levelN_name` 으로 맞춤. L2 `fill_card`(카드 빈칸 자리), L6 `hole_card`(첫 구멍) 를 레벨 데이터에 넣음.

## 문제·남은 일
- (major, orchestrator 결정) **K1 몰림 한도 해석**: 요청 "≤ 30 %" 를 쌍 5~6 레벨에는 그대로, 쌍 4 레벨(L3·L4)은 max(30 %, 1.5/쌍 수) = 37.5 %, 쌍 3(L1·L2)은 정보로만 적용. 근거: 쌍 4 판 300개를 숙련·중간 봇으로 재 본 최저가 30.0 %(고른 몫 25 %), 쌍 3 은 고른 몫 자체가 33 %. L4 는 30 % 도 만족, L3 만 33 %(중간 봇). 엄격 30 % 를 원하면 L3 를 쌍 5개 판으로 바꾸는 안이 있음(그때 L5 "색 하나 더" 새 요소를 다른 것으로).
- (minor, 1-2 안건, art·lore) 플레이 중 % : balance 는 **판 채움 %** 채택(art 도 같은 의견), lore 는 "표시 안 함" 의견 → 1-2 에서 확정. balance.json `percent.in_play` 하나만 바꾸면 됨.
- (minor, 1-2 안건, art) 판정 이름 자리: 30-art A1(판 밖) 을 balance.json 에 채택했음. lore 6-1 "짝 점 위" 와 1-2 에서 맞춤.
- (minor, balance·art) 칸 px 검사(V1)는 판 옆 기둥·세로 예약 200 px 가정. 30-art layout(여백 12 px, 6열 54.9 px)과 결론 같음. layout.json 확정 뒤 V1 을 그 값으로 바꿀지 1-2 에서 결정.
- (minor, orchestrator) 아동 테스트(00-benchmark K2): 봇 ε·p_cut 근거가 없음. L1~L3 와 L2 빈칸 신호가 글 없이 읽히는지 확인을 권함.

## 다른 팀에 줄 인사이트
1. [flow-01] **유일해 검증기에 생성용 가지치기를 넣으면 안 된다(실측)**: "자기 선과 이웃한 칸 금지"를 넣은 검증기는 F2 판 1,200개 중 유일하지 않은 26개 중 23개를 유일로 통과시키고, 지름길 자리가 있는 정답은 아예 버려 "답 0개"를 낸다. 검증기 가지치기는 "답을 버리지 않음"이 증명된 것(막다른 빈칸·끊긴 색·덮을 수 없는 빈칸 덩어리)만 쓰고, 작은 판은 가지치기 0 열거로 교차한다. 근거: `projects/flow-01/tools/trap-check.mjs`, 20-balance 6-3. 적용: 퍼즐 생성기를 만드는 모든 balance.
2. [flow-01] **"빈칸 함정" 같은 학습 요소는 생성 필터가 지워 버릴 수 있다**: 유일성을 위해 넣은 "자기 선 이웃 금지"(F2)를 켜면 4x4 판 2,948개 중 곧은 길로 다 이어도 빈칸이 남는 판이 0개였다. 그 레벨만 필터를 끄고 정확한 검증기로 유일 판을 골랐다(유일 비율 98 % → 35 %). 근거: 20-balance 6-3. 적용: 레벨마다 가르칠 요소가 필터에 막히지 않는지 먼저 센다.
3. [flow-01] **몰림(한 곳 30 %) 같은 비율 지표는 실행 수가 아니라 사건 수로 표본을 정한다**: 숙련 봇 헛 이동은 한 실행에 몰려 나와, 3000회(헛 이동 21~230회)에서 28 % 였던 판이 다른 시드에서 34 % 가 됐고 헛 이동 400회에서도 ±4 %p 흔들렸다. 사건 ≥ 2000 회까지 늘리고(최대 20만 회), 숙련 봇이 거의 안 틀리면(헛 이동 < 1 %/회) 중간 봇으로 잰다. 근거: `verify-levels.mjs` K1, 20-balance 7-4. 적용: runner·rhythm 의 σ25 몰림 검사도 "사망 ≥ N 회"로 표본을 잡을 것.
4. [flow-01] **"지점"이 적은 코어에서는 30 % 몰림 기준을 지점 수로 읽는다**: 위험 지점이 쌍 3~6개뿐이면 고르게 나눠도 33 %·25 % 라 30 % 가 불가능하거나 "완전히 고름"을 요구한다. max(30 %, 1.5/지점 수) 로 읽으면 지점 5개 이상에서 원래 기준과 같다. 근거: 20-balance 7-4. 적용: 판정 대상이 적은 코어의 balance·qa(오케스트레이터 승인 필요).
5. [flow-01] **이동 수처럼 정수인 분포의 중앙값은 보간 중앙값으로 판정한다**: 실패가 없어 "첫 시도 클리어율 p"가 없는 코어는 rhythm-01 의 ln0.5/ln(1−p) 대신 x − 0.5 + (N/2 − 아래 개수)/x 개수 로 같은 목적(정수 경계 뒤집힘 방지)을 얻는다. 짧은 실행(200회)의 m̃ 는 ±5 % 흔들려(5x5 판 6.76 → 8000회 7.19) 후보 고르기도 3000회 이상으로 한다. 근거: `tools/sim/bots.mjs` moveStats, 20-balance 7-1. 적용: 퍼즐·실패 없는 코어의 balance·qa.
