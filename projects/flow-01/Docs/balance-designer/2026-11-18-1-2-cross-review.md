# 1-2 교차 리뷰 1차 (balance → lore·art)

- 날짜: 2026-11-18
- 역할: balance-designer
- 프로젝트: flow-01
- 단계: 1-2 교차 리뷰 1차

## 요청 받은 일
오케스트레이터가 요청했습니다. lore(10-lore, strings)·art(30-art, assets) 문서를 밸런스 데이터와 대조해 충돌·빈틈을 이슈 목록으로 씁니다. 중점은 다음과 같습니다.
- layout 칸 px·예약 영역 ↔ V1 200 px 가정
- `color_slot` ↔ palette
- 연출 시간 ↔ 판정·1.0 s 잠금
- 판정 이름 등급 ↔ 이동 수 경계
- 카드 그림 좌표 ↔ L2 fill_card·L6 first_hole
F1~F5를 따르고, 이번에는 내 문서를 고치지 않습니다.

## 한 일
1. 공통 문서, F1~F5, lore·art 전체와 assets JSON 3개, levels 10개, board.mjs의 표시층 함수를 읽었습니다.
2. layout.json의 20경우(4해상도 × 5판 크기)를 balance V1 식과 node로 비교했습니다. 예약 200 px 가정은 실제 판 밖 공간(세로 238~590, 가로 296~359 px)보다 작습니다. 그래도 칸 크기를 정하는 축이 아니어서 칸 px는 ±0.5 px 안에서 같고, 최소는 54.9(art)와 54.7(balance)로 결론이 같습니다.
3. 튜토리얼 SVG 3장의 좌표를 칸 번호로 바꿔 레벨 데이터와 비교했습니다. storyboard·card-fill·card-hole 세 장 모두 실제 판과 다릅니다.
4. 연출 시간을 판정 시간·잠금 시간과 맞춰 봤습니다. 판 완료 시간표는 1.0 s 안에 끝납니다(마지막 띠 850 ms). 빈칸 숨 쉬기 시작(600 ms)은 판정 이름 끝(630 ms)보다 이릅니다. 결과 버튼은 1.0~1.28 s 사이에 눌릴 수 있습니다.
5. 표시층 정의를 대조했습니다. fillPct(이어지지 않은 선 포함)와 art의 "칠한 칸"(연결된 쌍만)이 다르고, 결과 %를 설명하는 EN 문장이 식과 다르며, "한 번에 이은 쌍" 표시가 art·lore에 없습니다.
6. 키 이름을 대조했습니다. 레벨 이름 ↔ 테마 10/10 일치, color_slot ↔ palette 일치, 등급 키 3종이 서로 이어지지 않음, 카드 키 없음.
7. 원본 보호 grep 결과는 0건입니다(금지어 목록 정의 제외).

## 다른 팀에 줄 인사이트
- 튜토리얼 그림 카드(SVG)는 기획 병렬 단계에서 레벨보다 먼저 그려지는 일이 많습니다. 그러면 "그림 = 실제 첫 물체" 원칙을 문서에 적어 두어도 그림 3장이 모두 어긋날 수 있습니다. SVG 좌표를 칸 번호로 바꿔 레벨 데이터(빈칸·구멍·시연 길)와 비교하는 검사를 check 도구에 넣으면 사람 눈 검사보다 확실합니다. 근거: projects/flow-01/reviews/plan-1-2/balance-designer.md 이슈 1·2·4. 적용: art-director·qa-engineer.
- 진행도 %(판 채움)를 "선이 지나는 칸"으로 세면, 연결된 칸만 칠하는 그림과 숫자가 어긋납니다. 표시 숫자는 화면에 칠해진 것과 같은 집합을 세야 합니다. 근거: 같은 파일 이슈 7. 적용: balance-designer·game-developer.
