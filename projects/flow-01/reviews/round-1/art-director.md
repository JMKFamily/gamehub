### 화면에서 본 것 (요약)
- **플레이 화면은 30-art대로이고 모던함이 실제로 남**: 밝은 2색 바탕 + 흰 둥근 판 카드, 격자선 없는 둥근 타일 + 가운데 점, 칸 폭 60 % 둥근 띠, 연결 시 고리·tint 물듦·원 조각, 판 밖 판정 이름(쌍 shade + 흰 테두리)·작은 채움 %. 원작의 검은 바탕·발광 선과 반대 톤.
- **둘레·안쪽 구멍**: 플레이 판에서 둘레 구멍 L6 (4,2)은 판 외곽선이 오목하게 파이고 안쪽 모서리가 둥글며, 안쪽 구멍 (1,3)은 점 없는 바탕색 칸 + 둘레 선(`1280x720-ko-play-L6-judge.png`) — 규칙 그대로. 결과 미니 판만 둘레 구멍을 파내지 않음(이슈 6).
- **튜토리얼 카드 = 레벨 첫 등장**: L2 빈칸 카드·L6 구멍 카드, tutorial.mjs 검사 통과. L6의 둘레 구멍(파낸 모양)은 카드가 보여 주지 않음(안쪽 구멍만) — 같은 개념이라 이번엔 이슈로 세지 않음.
- **판정 이름·% 자리**: 세로는 판 위 띠·짝 점 x(412 "최고야" 32 % / "멋져" 53 %), 가로는 짝 점 열로 고른 기둥(640·1280 왼쪽 기둥). 판·쌍 점 줄·버튼과 겹침 없음, 크기 순서 이름 > %.
- **번쩍임·흔들림 0**: 코드에 화면 흔들림·전체 밝기 변화 없음(판 완료 1.03배 튐, 흰 45 % 띠는 선 위에만). 동작 줄이기 화면에서 조각·띠 없이 판정 이름·tint만 남음.
- **흑백**: L10 6쌍 표지(하트·동그라미·별·세모·달·네모)가 흑백에서도 구분, 쌍 점 줄 = 판 점 그림.

### 성능 major(QA #1·#2 동의) — 그림 쪽 원인과 단순화 제안 (새 이슈로 세지 않음)
QA LoAF에서 레벨 시작·메뉴 전환 긴 프레임이 스크립트 밖(페인트·래스터)이었습니다. 빌드 소스로 본 그림 쪽 후보:
1. `drawPlay`가 **매 프레임 전체 화면** 그라디언트 `fillRect` + `drawDecor`(412x915 DPR3 = 1236x2745 ≈ 3.4 Mpx). 화면이 멈춰 있어도 매 rAF 다시 그림 → 바탕·decor는 레벨 시작 때 한 번 오프스크린(또는 `#play` CSS 배경)에, 매 프레임은 판 캐시 `drawImage`부터. 바뀐 것 없으면 그리기 건너뛰기.
2. 그림 카드: 그라디언트 12개 SVG를 `innerHTML`로 넣고 `box-shadow` + opacity 200 ms 페이드를 매 프레임 다시 그리는 전체 화면 캔버스 위에 얹음 → 부팅 때 카드 SVG를 `<img>`(Blob URL) + `decode()`로 미리 래스터, `will-change: opacity`. 이슈 3의 연장 페이드 그라디언트 제거도 같이.
3. 지도: 노드 미니 판 SVG 10개 + 점선(dasharray) 별 10개를 innerHTML로 → 미니 그림은 부팅 때 `<img>`로, 빈 별은 실선(이슈 7). 이슈 2(별 48 px)를 고치면 별 래스터 면적도 약 1/9.
4. 판정 이름 `strokeText` 6 px 흰 테두리 + `fillText`: 이름 3등급 × 쌍 색 비트맵을 레벨 시작 때 미리 그림(QA 제안과 같음).
