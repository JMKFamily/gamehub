## 1. 설계 의도

1. **박이 곧 목표.** runner-01은 박을 무시해도 깼습니다(00-benchmark 1절). 여기서는 판정이 "박까지 몇 ms"이고, 무늬를 안 읽고 다 치면(8분 격자 연타) 깨지지 않게 놓침 구역을 정했습니다(5절, 검증 S4·S5).
2. **5~6세가 놀 수 있는 박 간격.** 한 무늬 안 별 사이 최대 1 s, 레벨 1은 최대 1박(545 ms). 아동 선호 박 간격 400~500 ms, 1 s 넘는 간격의 어려움 [문헌].
3. **보고 → 따라 치기.** 새 무늬는 바로 앞 마디에서 북채가 먼저 쳐 줍니다(보여 주기 마디, 속 빈 별, 판정 없음). 검증기가 "새 무늬는 반드시 보여 주기 뒤"를 강제합니다(S7, 두 마디 무늬는 보여 주기 2마디).
4. **새 기믹은 레벨당 1개 이하, 그림 카드 1장.** L1 꽉 찬 별 + 북채 차례(핵심 규칙), L2 반박 별, L3 쉬는 박, L6 두 마디 무늬, L7 반박 4연속. 나머지 5개 레벨은 기믹 없음.
5. **난이도는 판정 창보다 배치로, 그리고 한 번 놀이 안에서 깰 수 있게.** 통과 창은 10레벨 동안 320 → 250 ms(78 %)로만 줄이고, 판정 별을 20~29개로 묶었습니다. 5~6세 대리 봇(σ70)이 모든 레벨을 일반 모드 중앙값 13회 이하로 깨고, 레벨 10은 "기존 3레벨 곡선을 이어 간 레벨 6" 수준(연속 중앙값 T 13.70회 ±20 %, L10 13.36회)입니다(11장, 요청자 지시, round-2 R3). 1-1의 "6부터 연습 모드가 정상 경로"는 버렸습니다.
6. **헛탭에 관대, 연타에 엄격.** 박과 먼 탭은 무시합니다. 벌을 받는 탭은 "별 바로 앞 140 ms" 한 구역뿐입니다.

### 4-2. 비대칭 여부: 통과 창만 늦은 쪽 +20 ms, 딱·좋아는 대칭

1. **남은 지연 오차는 늦은 쪽으로 쏠립니다.** 보정하지 못한 출력 지연, 터치 → 이벤트 지연은 모두 "늦게 침" 방향입니다 [추정].
2. **이른 쪽 경향은 이 코어에서 작다고 봅니다.** 공을 눈으로 따라가는 과제라 소리만 듣고 칠 때의 "일찍 치는" 경향이 약하다고 봅니다 [추정].
3. **봇 민감도가 뒷받침합니다** [봇, 8-2]. L1 bias 0과 +20 ms가 같은 최적(2회), -40 ms 5회, +40 ms 3회.
4. **딱·좋아를 대칭으로 둔 이유:** 등급은 박에 얼마나 가까웠나를 정직하게 보여 줘야 합니다.
5. 실측에서 탭 분포 중심이 +20 ms보다 크게 벗어나면 비대칭 폭이 아니라 **보정 값**을 고칩니다(8장).

## 5. 헛탭·놓침 구역·보여 주기 마디 탭

### 5-1. 판정 순서 (`tools/sim/judge.mjs` `judgeAttempt`)

1. **아직 안 친 가장 이른 별 하나만** 봅니다(한 별은 탭 하나만 씀).
2. 탭이 그 별의 통과 창 [t - early, t + late] 안 → 성공(딱/좋아/통과), 다음 별로.
3. 탭이 그 별의 **놓침 구역** [t - early - 140, t - early) 안 → **실패 "너무 일찍"**.
4. 그보다 이른 탭 → **무시**(헛탭 수만 셈. 등급·실패에 영향 없음).
5. 통과 창 끝(t + late)까지 탭이 없으면 → **실패 "놓침"**. 그 시각에 별이 깨짐.
6. 보여 주기·쉬는·카운트인 마디에는 판정 별이 없으므로 그 마디의 탭은 4번(무시) 또는 다음 별의 3번에만 해당합니다.

### 5-2. 놓침 구역의 세부

- **늦은 쪽 놓침 구역은 없습니다.**
- **앞 별의 통과 창 끝보다 앞으로는 넓히지 않습니다.** 반박 쌍처럼 별이 붙어 있으면 뒤 별의 놓침 구역이 사라져, 앞 별을 치고 한 번 더 친 손가락이 뒤 별을 깨지 않습니다.
- **폭 140 ms(검증 S9):** 바깥 끝이 8분 하나 이른 탭을 **덮어야** "빈 자리까지 8분마다 다 치기"가 실패하고(S5), 1박 이른 탭은 **무시해야** 박마다 손뼉 치는 아이가 벌을 받지 않습니다. 10레벨(110~140 BPM, 통과 앞 115~150) 모두 두 조건을 만족합니다.
- **셰이커는 정박에만(결정 10).** 반주 셰이커가 8분마다 울리면 아이가 빈 반박 자리를 따라 치고, 그 탭이 다음 별의 놓침 구역(8분 하나 이른 탭을 일부러 덮는 구역)에 들어갑니다. 그래서 `accompaniment.shaker_slots: even_only`. 반박 리듬은 북채 소리와 아이 탭 소리가 들려줍니다. 판정 별 자리의 타악은 곡에서 빼고 아이 탭 소리로 냅니다.
- **헛탭 영향 [봇]:** σ70 봇(헛탭 2 %, 탭 0.15~0.45 s 뒤)은 판정 별이 많고 붙어 있을수록 헛탭 손해가 커집니다. 그래서 곡선 설계는 해석식이 아닌 헛탭 포함 시뮬레이션으로 잡았습니다(11장).

### 5-3. 보여 주기 마디의 아이 탭 (결정 10)

| 항목 | 규칙 |

| 반응(화면·소리) | **헛탭과 같음**(art의 헛탭 반응 하나). 빛살·판정 없음 |

### 8-1. 판정 식과 가정

`오차 = (탭 event.timeStamp → 오디오 시간 변환) - (outputLatency + baseLatency) - 수동 오프셋 - 별 시각`

| 가정 | 값 | 비고 |
|---|---|---|
| 판정 기준 시계 | AudioContext 시간 | 화면도 같은 시간(들리는 시각)으로 공 각도를 그림 |
| 탭 시각 | `pointerdown`의 `event.timeStamp` → `getOutputTimestamp()` 대응으로 변환 | |
| 자동 보정 후 남는 오차 | **-20 ~ +40 ms** [추정] | 내장 스피커·유선. 블루투스는 +120~+220 [추정] |
| 수동 오프셋 | -200 ~ +300 ms | 8-3 보정 화면 |
| **보정 때와 플레이 때 자동 지연 차이 Δ** (round-3 R17) | **0 ~ 64 ms** [QA 실측] | 자동 지연 보고값(outputLatency + baseLatency)은 오디오 잠금 해제 직후 작은 값(Edge 10 ms)이었다가 약 0.1~0.3 s 뒤 실제 값(66~74 ms)으로 바뀜(QA round-2 1-6 `parts/firstrun.json`, Δ 56~64). 기기를 바꾸면(블루투스 연결) 플레이 중에도 바뀜. **판정은 Δ와 무관해야 함**: 아래 R11 읽는 법이면 남는 영향 0(8-3 R17 표, 검증기 정보 R17) |
| 자동 지연 읽는 시점 (round-3 R11) | 보정은 **탭마다 그 순간**, 판정은 **시도 시작마다**(재시작 포함), 시도 중에는 안 바꿈 | round-2 빌드는 보정 시작에 읽어 보정 내내 고정 → 이중 보정(score B1). 정의는 아래 "R11 정의" |

**R11 정의 (round-3, 다음 dev 빌드 `games/rhythm-01/js/calib.js`가 같은 이름으로 옮길 기준. 시뮬레이터 `tools/sim/calib.mjs` `autoStableAt`·`calibTapDiffR11`·`attemptComp`, `balance.json audio_latency.auto_latency_read`)**

- 기호: `autoNow(t)` = 시각 t에 읽은 (outputLatency + baseLatency) × 1000 ms. `a(x)` = 이벤트 x의 오디오 시각(ms, `event.timeStamp` → 오디오 시간 변환, 지연 빼기 전). `base` = 보정 첫 똑딱의 예약 오디오 시각, `beat` = 600 ms(100 BPM).
1. **보정 탭 하나의 오차**: 들리는 박 = 예약 시각 + 그 순간 autoNow. 그러므로
   `t = a(탭) − autoNow(탭 순간)`, `k = round((t − base) / beat)`, **`오차 = t − (base + k·beat)`** (t < base − beat/2이면 첫 박 전이라 버림).
   회 계산·최종값(사용 탭 3~8번째, 선형 보간 IQR, 두 회 비교, 12개 중앙값, |m| ≤ 30 미적용, 자름)은 8-4 그대로. 이렇게 얻은 m은 **자동 지연을 뺀 남는 차이**이고, 그대로 수동 오프셋으로 저장합니다.
2. **판정 보정값**: 시도 k의 `comp_k = autoNow(시도 k 시작) + 수동 오프셋`, 판정 오차 = `a(탭) − comp_k − 별 시각`. comp는 **시도마다 다시 읽고**(레벨 시작·실패 뒤 재시작·연습 구간 재시작) 시도 안에서는 바꾸지 않습니다(R9 표시값 = 판정값, 공도 같은 comp로 그림).
3. **재시작과의 관계**: 다시 읽기는 실패 순간 ~ 다음 시도 시작 사이 한 번. 바뀐 양 `dc = comp_new − comp_old`만큼 남은 재시작 시각(V 기준 `restartV` 등)을 같이 옮겨 **실패 → 다시 움직임 1.08 s(벽시계)를 그대로** 둡니다. 안 옮기면 1.08 + dc s가 되어 dc 64 ms는 1.144 s(허용 0.94~1.20 안)지만 dc > 120 ms(블루투스 연결 등)면 허용 밖입니다(검증기 정보 R17).
4. **첫 보정 전 안정 대기**: 잠금 해제 뒤 매 프레임 autoNow를 읽어, **잠금 해제부터 400 ms 이상** 지났고 **최근 250 ms 안 값의 (최대 − 최소) ≤ 2 ms**이면 안정 → 그때부터 1박 뒤 첫 똑딱. **1.5 s**가 지나면 안정이 아니어도 시작(1·2가 탭·시도마다 다시 읽으므로 이중 보정은 생기지 않음). 같은 대기를 잠금 해제 뒤 첫 시도(보정 없이 바로 레벨에 들어가는 경우)에도 씀. 대기 중 화면은 보정 화면 그대로(점·그림 그대로, 똑딱만 아직 없음).
   - 오케스트레이터 예시(250 ms·2 ms·1.5 s)에 **"잠금 해제 뒤 400 ms 이상"을 더한 이유**: 250 ms 창만 보면 보고값이 0.25~0.3 s에 바뀌는 경우 바뀌기 전 값(10 ms)으로 "안정"이 됩니다(검증기 정보: 바뀜 300 ms → 최소 시간 없으면 267 ms에 옛 값). 400 ms를 더하면 0.1~0.3 s에 바뀌는 관측 범위가 모두 바뀐 뒤 시작합니다. 그 뒤에 바뀌어도 1번 때문에 판정 영향은 없고(검증기 "보정 중 2500 ms에 바뀜" 행 = Δ 0), 대기의 몫은 탭하는 사람이 듣는 박 간격이 중간에 튀지 않게 하는 것입니다.
   - **재시작은 대기하지 않음**: 가장 이른 실패도 시도 시작 뒤 1.46 s(모든 레벨 첫 별 놓침 구역 시작 중 최소), 재시작은 그 1.08 s 뒤 = 2.54 s로 최대 대기 1.5 s보다 늦습니다. 판정 창·1.08 s 배분(6-1)은 그대로.
5. `calibAutoLat`(8-5 조건 B 비교 기준) = 보정 끝 순간 autoNow. 저장소 버전 키를 올려 round-2에서 잘못 저장된 오프셋은 옮기지 않고 첫 실행 보정을 다시 합니다(R11).

### 8-4. 보호자 보정 흐름 (1-3, 결정 9 보강, `audio_latency.guardian_calibration`·`guardian_gate`)

아이의 조작은 그대로 **화면 아무 곳 탭 1가지**입니다. 아래는 어른이 쓰는 화면이며, 플레이 화면에는 나오지 않습니다. 모든 신호는 그림이고 글은 aria 대체 글(lore 7-9 확정 키)만 씁니다.

| 단계 | 규칙 | 수치·키 |
|---|---|---|
| ① 첫 실행 | 타이틀 탭(오디오 잠금 해제) → 보정 화면. 화면 왼쪽 위에 **"어른과 같이" 그림**(큰 사람 + 작은 사람, 버튼 아님, 탭해도 반응 없음) | `first_run_picture` `assets/icon-together.svg`, 대체 글 `calib_with_grownup`. 설정에서 다시 할 때는 그림 없음 |
| ② 보호자 문(다시 하기) | 레벨 선택 화면 왼쪽 위 설정 버튼을 **2000 ms 길게 누르면** 설정이 열림. 한 번 탭 = 빈 고리만 600 ms(벌 없음), 일찍 떼면 고리가 200 ms 동안 비워지고 처음부터 | `guardian_gate.hold_ms` **2000**, `single_tap_hint_ms` 600, `release_early_empty_ms` 200, 대체 글 `guardian_hold`, 버튼 `btn_settings` |
| ③ 측정 | 100 BPM 똑딱 소리만(화면은 박에 맞춰 움직이지 않음). 점 8개가 탭마다 하나씩 참 → 다 차면 비우고 **한 번 더 8번**(2회) | `rounds` 2, `taps_per_round` 8, `visual_beat_cue` false, 대체 글 `calib_progress` |
| ④ 계산 | 회마다 3번째 탭부터 6개 사용. 한 회의 IQR > 150 ms → **그 회만 다시**(앞 회는 유지). 두 회 중앙값 차이 > 60 ms → 두 회 모두 다시. 다시 하기는 **흐름 전체에서 1번까지**, 그래도 안 되면 이전 오프셋 유지 | `use_from_tap` 3, `reject_iqr_ms` 150, `round_disagree_max_ms` 60, `max_retries` 1, `retry_rule`, 유지 알림 대체 글 `calib_kept` |
| ④-1 계산 정의 (round-2 R4) | **사분위 = 선형 보간**: 정렬 s(n개), 위치 (n−1)·q의 아래 값 + (위 값 − 아래 값) × 소수부. 6탭이면 Q1 = s[1] + 0.25(s[2] − s[1]), Q3 = s[3] + 0.75(s[4] − s[3]), IQR = Q3 − Q1. **중앙값 = 홀수면 가운데, 짝수면 가운데 둘 평균**(6탭 회 중앙값·12탭 최종값 모두 짝수) | `quantile_definition: linear_interpolation`, `median_definition: even_mean_of_middle_two`. 기준 = 빌드 `games/rhythm-01/js/calib.js`, 시뮬레이터 `tools/sim/calib.mjs`(같은 코드), 검증 C1 |
| ⑤ 적용 | 오프셋 m = **12개 (탭 - 박) 중앙값**. \|m\| ≤ 30 ms → 적용 안 함(자동 보정만), 그 밖 → m을 수동 오프셋으로(-200 ~ +300으로 자름) | `estimator` `median_of_all_used_taps`, `apply_only_if_abs_over_ms` **30**, `offset_clamp_ms` |
| ⑥ 끝 | 체크 그림(`calib_done`) 1 s 뒤 자동으로 넘어감. 다시 하기 버튼(그림 ↻ + 점) | 대체 글 `calib_redo` |

근거
- **30 ms 미적용 문턱:** 어른 σ40 12탭 중앙값의 잡음은 약 40 × 1.25 / √12 ≈ ±14 ms라 30 ms 넘는 값은 대개 진짜 지연입니다. 아이 1회(6탭, ±36 ms)의 60 ms 문턱을 그대로 쓰면 보통 기기의 +30~+40 ms 오차를 못 고칩니다.
- **2회 × 8번:** 1회보다 잡음이 √2배 줄고, 두 회를 비교해 "아무렇게나 친 경우"를 거릅니다. 어른에게 16번 톡은 약 10 s.
- **"남은 오차 재측정" = ④의 두 번째 회**: 두 회 차이가 60 ms를 넘으면 측정 자체를 믿지 않고 다시 합니다. 적용 뒤의 남은 오차는 8-5의 플레이 중 감지가 계속 봅니다.
- 1-2 `calibration` 블록(1회·±60)은 지우지 않고 공통값(BPM·탭 수·IQR·자름 범위)과 기록으로 남깁니다(`superseded_by: guardian_calibration`). 기록 행(8-3)도 같은 사분위·중앙값 정의로 잽니다.
- **정의를 빌드 쪽으로 통일한 이유(R4)**: 아이·보호자가 실제로 겪는 동작이 빌드이고, QA 독립 구현과 99/99 일치했으며, 선형 보간(type 7)은 표준 정의입니다. round-1 시뮬레이터(반올림 위치 사분위, IQR 실패 때 두 회 모두 다시)는 σ70 6탭 묶음에서 받아들임/버림이 6.0 % 달랐습니다(QA minor 5, balance 리뷰 이슈 4). 빌드는 바꾸지 않습니다.

### 17-1. 단위·용어

- **박(beat)**: 레벨 박 0 = 카운트인 다음 첫 박. 레벨 시간(ms) = (카운트인 4박 + 박) × 1박 ms. `tools/sim/path.mjs beatToMs`.
- **덩어리(chunk)**: 빈 정박 없이 이어진 별 묶음(별 사이 ≤ 1박). 화면에서 한 묶음으로 읽힘. 늘 정박에서 시작(반박 단독 시작·당김음 없음).
- **빈 박**: 앞 덩어리 마지막 별 박 p, 다음 첫 별 박 q 일 때 `q − floor(p) − 1`. 3.5박에 끝나고 빈 1박이면 다음은 5박.
- **마디 내용**: 한 마디 8칸(8분 자리 0~7)의 별 배열. 덩어리가 마디 선을 넘으면 두 마디 내용으로 나뉨. 파생 `patterns`의 id = `c` + 자리(예 `c046`).
- **미리 보기** = 별이 오른쪽 끝에 나타나 판정 북 중심에 닿을 때까지 = lead 박 × 1박. **판단 시간** = 미리 보기 − 이른 통과 창.
