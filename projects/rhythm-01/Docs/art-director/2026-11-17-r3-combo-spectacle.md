# round-3 콤보 파격 연출 시각·사운드 규격

- 날짜: 2026-11-17 (작업은 11-18 새벽까지, 사용 한도 정지 후 재개)
- 역할: art-director
- 프로젝트: rhythm-01 (똑딱북: Tickadrum)
- 단계: round-3 (QA 전 빌드 범위)

## 요청 받은 일
오케스트레이터가 요청자 지시 "콤보 파격 연출"의 시각·사운드 규격을 요청했습니다. 지시 내용은 세 가지입니다. 화면 가운데에 콤보 수를 크게 띄우고, 매칭 비율(%)은 타격 지점 가까이 두고, 콤보가 이어질수록 화면 전체 파티클을 키웁니다. 작업 중에 추가 지시 두 가지가 왔습니다. 하나는 balance 12세 재조정(판정 별 29~69개)을 반영하는 것이고, 다른 하나는 끝날 때 세 검사를 다시 돌리는 것입니다.

## 한 일
1. `30-art.md` 16-14절을 새로 썼습니다(1~8항: 레이어, 큰 콤보 수, 판정 글 자리, 단계 파티클, 소리, 움직임 줄이기, 성능, 다른 역할 요구). 대체된 줄은 지우지 않고 표시만 했습니다. 표시한 곳은 16-4 머리말과 안내문, 16-8 "콤보 숫자 금지"·"원형 폭발" 줄, 16-1 HUD 행, 16-9 대체 표 한 줄, 16-11 에셋 표 한 줄입니다.
2. 큰 콤보 수를 정했습니다.
   - 자리는 위쪽 가운데, HUD 띠 아래 +4 ~ 길 윗변 −4이고 위쪽에 맞춥니다.
   - 숫자 높이는 화면 높이 × 0.14입니다. 640x360만 13.2 %이고 하한은 12 %입니다.
   - 라벨은 점 3개 그림 + lore 새 키 `combo_label`입니다(권장 "연속"/"STREAK", "COMBO"·"콤보" 금지).
   - hud 단색이고 불투명도는 0.22, 튐일 때 상한 0.30입니다. 판정마다 100 ms 튀고, 단계에 닿으면 1.15배로 튑니다.
   - 끊기면 0.3 s 안에 소리 없이 작아지며 사라집니다.
   - 숫자 폭·높이(0.58/0.73 em)와 라벨 폭은 Edge 헤드리스 캔버스 measureText로 직접 쟀습니다.
3. 판정 이름 + %는 16-13 자리(길 아래, 판정 북 오른쪽)를 그대로 둡니다. 근거는 두 가지입니다.
   - 판정 선 바로 위는 공 뜀 자리이고, 그 위는 이제 콤보 수 자리입니다. 가로 화면은 높이가 32 px뿐입니다.
   - 지금 자리는 타격 지점에서 86~90 px 떨어져 있고 가림이 0입니다.
4. 파티클 단계는 10·20·30·50으로 정했습니다.
   - 별 수가 29~69개라 100은 어느 레벨에서도 나오지 않습니다. 그래서 L1은 2단계, L2~L4는 3단계, L5~L10은 4단계까지 닿습니다.
   - 단계마다 개수·지름·속도·불투명도 상한·색 수를 정했습니다.
   - 금지 구역(길 띠·공·판정 글·HUD)은 evenodd 클립으로 빼서, 별 뒤 바탕이 늘 길 색이 되게 했습니다.
   - 끊기면 0.3 s 동안 10 px 가라앉으며 사라지고 소리는 없습니다.
   - 타격 빛 파티클은 판정 선 왼쪽 ±30° 방향, 길 띠 안에만 나갑니다. 딱 4~12개, 좋아 2~6개입니다.
   - 움직임 줄이기에서는 바탕 파티클이 1/4로 줄고 정지합니다. 타격 빛은 0, 숫자 튐은 꺼집니다.
   - 성능 규칙은 메인 캔버스 하나, 풀 112칸, 채우기 호출 16회 이하입니다. 단계별 예산표를 두었고, 최대 104개입니다.
5. 소리: `combo_50` 화음(×8·12·16)과 steps["50"]을 추가했습니다. 크기 순서는 그대로입니다.
6. HUD 띠 안의 콤보 줄을 없애서 띠 아래끝이 77/73에서 66으로 올라갔습니다. 덕분에 가로 화면에도 숫자 12 % 이상이 들어갑니다.

## insights 적용
- 적용한 것:
  - 소리 크기 순서를 오프라인 렌더로 확인했습니다.
  - 값은 JSON 원본으로 두었습니다(표 파싱 아님).
  - 화면 고정 요소 자리를 데이터로 두고 4해상도에서 겹침을 검사했습니다.
  - 단계 값을 실제 판정 수로 정했습니다.
  - 끊김은 0.3 s 안에 무음으로 끝납니다.
  - 첫 그림을 미리 그리게 했습니다(스프라이트를 로딩 때).
  - UI 타이머는 게임 시계에 묶었습니다.
  - 클리어 때 HUD를 페이드합니다.
- 적용하지 않은 것과 이유:
  - runner-01의 "숫자 대신 점 10칸 + 10마다 큰 표지"와 djmax 4-4의 "단계 연출은 HUD 띠 안에서만"은 요청자 새 지시(가운데 큰 숫자, 화면 전체 파티클)로 대체됐습니다. 대신 금지 구역 클립으로 판정 대상 가림 0을 지킵니다.
  - "판정 표시는 판정선 바로 위"(djmax 2-2)는 공 뜀 자리와 겹쳐 따르지 않았습니다. 이유는 16-14-3에 적었습니다.
