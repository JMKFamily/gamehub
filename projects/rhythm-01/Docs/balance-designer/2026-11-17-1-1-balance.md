## 요청 받은 일
오케스트레이터가 코어 A "박자 시계 + 보여 주기 마디"의 밸런스 기획을 요청. 요청자 지시 요지: runner-01 핵심 재미 유지 + 리듬 맞추는 재미 강화, 범위는 기획까지(구현 없음, 검증 도구는 허용), 5~6세 단순 규칙(조작 1~2가지, L1 σ70 봇 첫 클리어 중앙값 5회 이하, 새 기믹 레벨당 1개 이하·그림 카드), **10레벨**(1~3 데이터, 4~10 곡선 표), 기존 리듬 게임 차트·레벨·판정 이름 베끼지 않기, runner-01 폴더 수정 금지.

## 한 일
1. 판정 창 확정: 딱 ±50 / 좋아 ±100(L3부터 ±90) / 통과 L1 -150~+170, L2 -135~+155, L3 -125~+145 ms. 통과 창만 늦은 쪽 +20 ms 비대칭(남은 지연 오차가 늦은 쪽으로 쏠림 + bias 민감도 봇 결과).
2. 헛탭·놓침 구역 규칙: 통과 창 바로 앞 140 ms만 실패 구역(앞 별 창 끝에서 잘림), 늦은 쪽 구역 없음, 나머지 탭 무시. 8분 하나 이른 탭은 덮고 1박 이른 탭은 무시하도록 폭을 정함.
3. 재시작 1.08 s 배분(페이드 0.06 / 깨짐 0.40 / 정지 0.40 / 복귀 0.28), 카운트인 1마디, 연습 모드 체크포인트 = 쉬는 마디 시작, 별 등급 1~3 기준(좋아 이상 75 %, 딱 60 %).
4. 오디오 지연 보정 가정과 판정 영향(남은 오차 bias −80~+100 ms 민감도 표).
5. 박 단위 레벨 스키마(8분 자리 0~7, show/play/rest 마디, 무늬 사전, 체크포인트, 그림 카드 키) 정의, 레벨 1~3 데이터 작성. 10레벨 곡선 표(BPM, 길이, 별 수, 무늬 종류, 통과 창, 새 기믹, 해석 예측).
6. 검증 도구 작성(node만): `tools/sim/judge.mjs`(판정 기준 구현), `tools/sim/bots.mjs`(σ25/50/70/90 봇, 연습 모드), `tools/verify-levels.mjs`(S1~S11 구조 검사, B1~B4 봇 검사, 정보 출력). 첫 실행에서 L3 σ70 중앙값 13회(한도 12)로 FAIL → 별 32 → 28로 줄여 해결. L2 미사용 무늬 B 제거.
7. 10-lore.md 질문(Q2·Q3·Q4·Q5·Q8·Q9)에 답하고 lore·art·오케스트레이터 질문 목록 작성.
