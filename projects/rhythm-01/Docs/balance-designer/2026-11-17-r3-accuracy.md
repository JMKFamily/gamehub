(1) `balance.json accuracy` 블록에 공통안 % 계단을 레벨 실제 창 값으로 정의합니다(L3 좋아 ±90 포함, 판정 창은 바꾸지 않음). 레벨 정확도와 기록 규칙을 넣고, 등급 경계와 % 칸 경계가 어긋나지 않는지 확인합니다. (2) 20-balance 17장에 절을 덧붙이고, 봇 분포를 검증기 INFO로 냅니다. (3) % 표시가 판정·클리어·30회 한도·B6에 영향이 0임을 확인합니다. 전체 실행 ALL PASS를 보고합니다.

## 한 일
1. `balance.json accuracy` 블록을 새로 넣었습니다(기존 키 변경·삭제 없음, 같은 1칸 들여쓰기).
   - 식 키: `perfect_inner_ms` 25(100 %), 딱 끝 90 %, `good_bins` 3(80/70/60), `pass_bins` 5(50~10), W = e 쪽 창 끝(`window_end_side`), 경계 `inclusive_inner`, 실패는 % 없음, `grade_from_pct`
   - 거울 표 `levels`(L1~L10 칸 끝 d, 이른·늦은 쪽 따로)
   - `level_accuracy`: mean_floor, 클리어만, 실패·연습은 내지 않음, 플레이 중 평균 없음
   - `record`: 일반 모드만. 최고 정확도는 일반 클리어 중에서, 최고 콤보는 일반 시도(실패 포함) 중에서
   - `display_timing_ms`: 공통 7-3의 80/400/150 ms와 바꿔 그리기
   - `affects`: 10개 전부 false
2. `tools/sim/bots.mjs`에 `accuracyPct`·`gradeFromPct`·`levelAccuracy`를 덧붙였습니다(기준 구현, 기존 코드 변경 없음). `judge.mjs`는 읽기만 했습니다.
3. `tools/verify-levels.mjs`에 새 검사와 정보 행을 넣었습니다.
   - **A0**: 키·affects·거울 = 식
   - **A1**: 레벨마다 e 전 구간을 0.05 ms 격자와 경계값으로 훑어 % → 등급 = 판정 등급을 봅니다. 창 끝 10, 창 밖 없음, 단조, 10칸, 봇 판정 대조도 같이 봅니다.
   - **A2**: % 를 센 뒤 judgeAttempt 결과 불변 + 정보(B1·B6 원천 L1·L3·L10 다시 계산 값이 같음)
   - **정보 A3**: σ25/50/70 클리어 시도의 레벨 정확도 분포
4. (재개 뒤 lore R3-12 요청 반영) 키 이름은 `accuracy` 하나입니다. `judge_pct`는 예시 이름이라 따로 두지 않고 `_key_note`에 적었습니다. 신기록 표지 조건 `record.new_record_mark`를 정했습니다: 최고 정확도에만, 이전 최고가 있고 이번 값이 그보다 클 때만 표지를 띄웁니다. 첫 클리어·같은 값·최고 콤보·연습에는 표지가 없습니다(lore 가정 확정). A0에 이 조건을 넣고 전체 실행을 다시 했습니다.
5. `20-balance.md` 17-14(식, 레벨별 칸 경계 표, 정확도·기록, 봇 분포, 불변 확인, 넘길 값, insights 적용, 남은 위험)를 썼습니다.

## 검증 결과
`node projects/rhythm-01/tools/verify-levels.mjs`(전체, --quick 아님)는 **종료 0, FAIL 0, ALL PASS (PASS 308줄)**로 끝났고, 4분 35초 걸렸습니다. 신기록 조건을 넣은 뒤 다시 돌린 전체 실행도 같은 결과입니다(A0에 신기록 조건 포함, 값 모두 같음).
- **등급 경계와 % 칸 경계가 어긋나지 않습니다**. A1: L1~L10 격자·경계 5088~6488점에서 % → 등급 다름 0, 봇 판정 레벨당 25,123~32,126개에서도 다름 0입니다. 창 끝 = 10, 창 밖 = 표시 없음, % 단조, 양쪽 10칸이 모두 나옵니다. 등급 경계 50 / g / W가 그대로 % 칸 경계이고 둘 다 "이하" 규칙이라 그렇습니다.
- **영향 0**:
  - A2: 5000시도를 다시 판정해도 다름 0건입니다.
  - 정보 A2: B1·B6 원천을 다시 계산한 값이 앞과 같습니다. L1 3회(2.793), L3 7회(6.513), L10 21회(20.99)입니다. B6은 T 23.19 → L10 20.99(−9.5 %)이고, B6s 평균 −11.1 %로 앞 실행과 같습니다.

## insights 적용
- 적용한 것: 퍼센트 판정 줄(계단·같은 Δ·정확도 = 클리어 평균 내림·실패/연습은 내지 않음), 콤보 보상 층·봇 불변 방식, 연속 중앙값 한 원천, QA 도구에 값 박지 않기
- **적용 안 함**: 판정 이름 줄 중 이름 문구·글자 크기·글꼴입니다. lore·art 소유라 balance는 표시 시간 키만 두었습니다.
- 해당 없음: 레벨·판정 창을 바꾸지 않았으므로 레벨 설계 항목은 대상이 아닙니다. 구현·실측 항목은 범위 밖입니다.
