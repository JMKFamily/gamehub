- 날짜: 2026-11-17

## 요청 받은 일
요청자가 "판정 이름과 퍼센트까지 해주세요"라고 지시했고, 오케스트레이터가 그 문구 작업을 맡겼습니다. 할 일은 판정 이름 3개 키(KR·EN) 확정, % 표기 형식, 결과 화면 정확도·최고 콤보 문구, aria 규칙입니다. 지난 교차 리뷰에서 남은 낱말 4곳(R3-1·R3-4 L10·R3-5·R3-6)도 함께 정리합니다. 요청자 규칙은 다음과 같습니다: 5~6세 단순 규칙, 약한 아트 컨셉, 원본 보호(DJMAX 판정 이름·용어 금지), 결제·광고·계정 금지, git 실행 금지(`--version` 포함), 산출물 3개 외 수정 금지, 서버 사용 안 함, 이름 가안 유지, 선작업 금지.

## 한 일
1. **판정 이름 확정 (10-lore R3-12-1)**: `judge_perfect` 딱이야 / Wow!, `judge_good` 좋아 / Nice, `judge_pass` 됐어 / OK. 실패 칸에는 키를 두지 않았습니다.
   - 기존 등급 이름과의 관계: 기획 이름(딱·좋아·통과)과 데이터 키(perfect·good·pass)는 그대로 두고, 화면 말만 공통 권장안을 씁니다.
   - 근거 1: "딱"은 1글자라 2~3글자 기준에 맞지 않고, 같은 순간 나는 탭 소리와 겹칩니다.
   - 근거 2: "통과"는 시험 말투인데, 3단도 콤보가 이어지는 성공입니다.
   - 근거 3: 세 게임이 같은 말을 쓰면 아이가 게임을 바꿔도 같은 말이 같은 등급입니다.
   - 채택하지 않은 안: STATUS 후보였던 "딱·좋아·통과를 화면에 그대로", 공통 문서 대안 "최고".
2. **% 표기 (R3-12-2)**: 정수 + "%", 띄어쓰기 없이 씁니다("90%"). 두 언어가 같고 번역 키는 없습니다.
   - 이름이 위, %가 아래 작게 두 줄로 씁니다. "이름 + %" 한 줄 표기는 원작 표기라 쓰지 않습니다.
   - 나오는 값은 딱이야 100·90, 좋아 80~60, 됐어 50~10입니다.
3. **결과 화면 (R3-12-3)**: 키 2개를 새로 만들고 1개를 다시 씁니다.
   - 새 키 `result_accuracy`: 잘 맞힌 정도 / How well you hit.
   - 새 키 `result_new_best`: 가장 잘 맞혔어요 / Your best timing yet. 정확도 신기록 표지에만 씁니다.
   - 다시 쓰는 키 `aria_streak_best`: 가장 길게 이어 침 / Best streak, 문구 그대로입니다. 쓰지 않던 이유(결과 화면 없음)가 사라졌습니다.
   - 화면 글은 숫자만 둡니다("87%", "23"). 앞 이름표는 그림입니다.
   - 실패한 시도와 연습 모드 클리어에서는 정확도·최고 콤보를 보여 주지 않습니다.
4. **aria (R3-12-4)**: 판정 이름·%는 판정마다 읽지 않습니다. 캔버스에 그리거나 `aria-hidden`으로 두고, `aria-live`는 만들지 않습니다.
   - 정확도와 최고 콤보는 `role="meter"`이고 값은 `aria-valuenow`로 넘깁니다.
   - `aria-valuetext`에는 정확도는 "87%", 최고 콤보는 숫자만 넣습니다.
   - 플레이 화면 `aria_streak`도 R3-a의 "valuetext 없음"을 "숫자만"으로 바꿨습니다(insights 콤보 대체 글 줄).
   - 레벨 카드에 표지를 그린다면 버튼 밖에 두거나 `aria-describedby`로 잇습니다.
5. **교차 리뷰 낱말 정리**: 키·숫자는 바꾸지 않았습니다.
   - R3-1: "북 옆에" → "화면 위 띠에"(art 16-4).
   - R3-4 L10: "1~9에서 만난 여러 묶음이 다시 찾아오고, 끝은 붙은 별 셋으로 닫음". 데이터는 무늬 11개 중 8개를 쓰고 C·W·Y가 없으며 마지막이 Z입니다.
   - R3-5: "별이 북에서 터짐" → "판정된 별·이펙트가 길과 함께 흐름"(art 16-3).
   - R3-6: "판정 북 위에" → "판정 북 바로 아래"(art 16-1).
6. **앞 절 대체 표시**: "판정 글 없음" 규칙이 있던 7곳에 R3-12 보완·대체 표시를 달았습니다(확정값 표, 6-2, 7절 원칙, R3-0 두 줄, R3-7, R3-a·R3-b, R3-9). 기존 문장은 지우지 않았습니다.

## 검증 결과
- **node 파싱 결과**: 스크래치 `count-keys.mjs`로 셌습니다. 첫 칸이 "키"인 표에서 키를 뽑고, 같은 키는 하나로 셉니다. 첫 칸의 "다시 씀"은 사용으로 셉니다.
  - **표 키 75개**, 폐기 3(`tut_tap`·`card_star_tap`·`card_two_bar`), 쓰지 않음 1(`card_long_row`), **사용 71**.
  - 이전 70개는 모두 남았습니다(삭제 0, 기존 키 문구 변경 0).
- **새 키 문구 길이**(node `[...s].length`, 단어는 공백으로 나눔): 딱이야 3자, 좋아 2자, 됐어 2자, 잘 맞힌 정도 7자, 가장 잘 맞혔어요 9자. 영어는 1·1·1·4·4단어입니다. 모두 12자·6단어 이내입니다.
- 줄바꿈은 774줄 모두 CRLF입니다(섞임 없음).
- 빌드·접근성 트리 확인은 하지 않았습니다. 구현 전이고, 서버를 쓰지 않는다는 규칙 때문입니다.
- insights 적용:
  - 퍼센트 판정 줄: 계산식은 balance 몫이라 문서에는 적지 않고, 값 범위만 문구에 맞췄습니다.
  - 판정 이름 줄: 이름 확정. 글자 높이 28 px와 %를 이름의 0.5~0.6배로 하는 것은 art에 넘겼습니다.
  - 콤보 대체 글 줄: R3-12-4에 반영했습니다.
  - 12자 이내 줄, 모양 이름 줄, ariaSnapshot 줄: 지켰습니다.

## 문제·남은 일
- **minor · art**: 30-art 16-3의 "판정 글자·숫자 없음" 줄과 16-8 "판정 글자 팝업 … 판정 %" 줄을 이번 지시 범위만큼 풀어야 합니다. 공통 문서 7-6이 권하는 자리 "판정 북 바로 위"는 우리 화면에서 길 띠, 곧 별이 지나는 자리입니다. 그래서 다음 별 읽기 영역, L1 손가락, `tut_drum_tap` 글 자리와 겹치지 않는 자리를 `layout.json`에 정해야 합니다. 노랑 `star`는 글자에 쓰지 않습니다.
- **minor · balance**: `judge_pct` 키를 정하고, 신기록 표지 조건("첫 클리어는 표지 없음" 가정)을 확인해야 합니다.
- **정보 · 아동 테스트**: "됐어"가 거절("그만")로 들릴 위험이 있습니다. 그런 반응이 나오면 예비안 "맞았어 / Got it"으로 바꿉니다(키 그대로).
- **정보**: `clear_title` EN "Great job!"은 round-1부터 있던 일반 칭찬 문장이라 그대로 두었습니다. 판정 이름 자리에는 쓰지 않습니다.

## 다른 팀에 줄 인사이트
- 판정 이름처럼 화면 말을 기획 이름과 다르게 정할 때는, 데이터 키·기획 이름·화면 키를 한 표의 한 줄 짝으로 묶으면 문서·데이터를 고치지 않고 화면 말만 바꿀 수 있습니다. 키 열을 표 첫 칸에 두어야 키 수를 세는 파서가 놓치지 않습니다. 근거: 10-lore R3-12-1. 적용: lore-writer.
