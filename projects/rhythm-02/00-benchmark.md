## 1. 유지할 핵심 재미 (같은 맥락)

runner-01·rhythm-01에서 이미 분해된 재미 원천 F1~F6(`projects/rhythm-01/00-benchmark.md` 1절)을 그대로 기준으로 씁니다.

| # | 재미의 원천 | 앞 두 게임의 근거 | 새 코어에서의 뜻 |
|---|---|---|---|
| F1 | 원터치 타이밍 손맛 | runner 단독 가시 이륙 창 0.269 s [실측], rhythm-01 L1 통과 창 320 ms [rhythm-01 설계] | 탭 하나 = 북이 톡 올라가 공을 친다. 맞추는 대상은 "공이 북에 닿는 순간" |
| F2 | 실패 비용 거의 0 | 사망 → 다음 시도 1.11 ± 0.03 s, 자동 [실측], rhythm-01 1.08 s | 그대로. 공이 떨어지면 약 1.1 s 뒤 자동 재시작, 결과 화면 없음 |
| F3 | 구간 암기 → 숙달 | runner 장애물 배치 암기, rhythm-01 마디 무늬 암기, % 진행도 막대 | 암기 단위 = **튀는 길이의 줄(긴 통·짧은 통의 순서)**. 노래 가사처럼 "통 통 큰통-- 통통"을 외움. % 진행도 막대 유지 |

| F5 | 박에 맞는 순간의 쾌감 | rhythm-01이 박 기준 ms 판정(딱/좋아/통과)으로 살림 | 그대로 박 기준 ms 판정. 맞은 정도는 공이 튀는 소리·빛으로만 구분(살아남는 조건은 "통과" 하나) |
| F6 | 톱니형 난이도·숨 고르기 | 어려운 구간 뒤 쉬는 구간, 새 기믹 안전한 첫 등장 | 그대로. 숨 고르기 = **받침 쉼**(공이 북 위에 앉아 한 마디 쉼, 3-2) |

**새 코어가 앞 두 게임보다 더 잘 하려는 것** (rhythm-01 round-1 교훈 반영, 11절):
- **신호가 적다.** rhythm-01은 궤도·별(진한/흐린)·북채·점선 궤도·손가락이 같은 화면에 있어 "볼 차례/칠 차례" 신호가 겹쳤습니다(round-1 major M1). 새 코어는 판정 대상이 **공 하나**이고, 칠지 말지를 알려 주는 별도 차례 신호가 없습니다. "공이 내려오고 있다" 자체가 유일한 신호입니다.
- **원인과 결과가 몸으로 보인다.** 내가 친 공이 올라가고, 안 치면 떨어집니다. 실패 이유(일찍 쳐서 헛스윙 / 늦어서 떨어짐)가 글 없이 보입니다.
- **판정을 눈에 보이는 접촉에 맞춘다.** 공이 북에 닿는 장면은 눈으로 따라가는 단서라, 오디오 출력 지연(블루투스 등)이 판정을 깨지 않게 설계할 수 있습니다(4-4).

## 2. 후보 코어

모두 조작은 탭 1가지이고, 실패 → 약 1.1 s 자동 재시작, % 진행도 막대를 공통으로 씁니다(아래 항목에서는 차이만 적음).

### 후보 A. 통통 공받기 — **선정**

- **한 문장 규칙**: 공이 북에 떨어질 때 톡 쳐서 다시 올려 보내고, 공을 떨어뜨리면 다시 시작한다.
- **조작**: 화면 아무 곳 탭. 탭하면 화면 아래 가운데 북(받침)이 짧게 톡 올라갑니다.
- **리듬이 중심이 되는 방식**: 공이 북에 닿는 순간이 박(또는 반박). **공이 높이 뜰수록 다음 박까지 오래 걸립니다**(높이 = 시간, 5-2). 레벨이 정한 높이로 튀므로 "작은 통 = 1박, 큰 통 = 2박, 구름까지 = 4박"이 그림 그대로 리듬 길이(긴 음·짧은 음)가 됩니다. 판정은 탭 시각과 접촉 시각의 차이(ms). 친 순간 북 소리가 나서 곡의 빠진 북 파트를 아이가 채웁니다.
- **실패·재시도**: 늦으면 공이 북 옆으로 떨어져 굴러감, 조금 일찍 치면 헛스윙(북이 내려오는 중에 공이 닿아 미끄러져 떨어짐) → 실패 → 약 1.1 s 뒤 자동 재시작. 많이 이른 탭은 북이 제자리로 돌아온 뒤라 무시.
- **5~6세 적합성**: 매우 높음. 풍선·공 떨어뜨리지 않기 놀이와 같습니다. 한 번에 볼 것이 공 하나.
- **아트 단순성**: 매우 높음(원, 둥근 사각형, 타원 그림자).
- **구현 난이도**: 낮음. 물리 엔진 없음(공 높이는 시계의 함수, 5-2). 오디오 시계·재시작 구조는 runner-01·rhythm-01 것을 복사해 고쳐 씀.
- **위험**: ① 짧은 통(반박)은 공이 낮게 빨리 튀어 미리 볼 시간이 짧음 → 레벨 5 이후, 짝으로만(6절) ② 봇(σ70)은 "높이 읽기" 부담을 모르므로 두 공·짧은 통 레벨에서 봇이 실제보다 쉽게 볼 수 있음(12절 K2) ③ rhythm-01이 버린 후보 D(떨어지는 공 북 레인)와 "공이 북으로 내려온다"는 단서가 닮음 → 스크롤 레인·여러 노트 없음으로 구분(2-3).

### 후보 B. 박자 탑 쌓기 (크레인)

- **한 문장 규칙**: 좌우로 오가는 크레인이 탑 위 가운데에 올 때 톡 쳐서 블록을 떨어뜨려 쌓고, 블록이 탑에서 떨어지면 다시 시작한다.
- **조작**: 탭 1가지(블록 놓기).
- **리듬 중심 방식**: 크레인이 박마다 가운데를 지남. 어떤 박에 놓을지는 크레인에 블록이 매달려 있는지로 정함(빈 갈고리 = 쉼). 판정은 가운데 통과 시각 기준 ms(가로 어긋남으로 보임).
- **실패·재시도**: 블록이 탑을 벗어나 떨어지거나 블록을 매단 채 가운데를 지나치면 실패.
- **5~6세 적합성**: 높음(쌓기 놀이). 탑 높이가 곧 진행도라 보기 좋음.
- **아트 단순성**: 높음.
- **구현 난이도**: 낮음~중간.
- **위험**: **리듬을 미리 보여 줄 장치가 따로 필요.** 갈고리에 블록이 실리는 순간은 가운데 도착 반 박 전이라 판독 시간이 너무 짧고, 다음 무늬를 보이려면 블록 대기 줄(위쪽 컨베이어)을 하나 더 그려야 합니다. 그러면 화면에 움직이는 흐름이 둘(크레인 + 대기 줄)이 되어 rhythm-01 M1과 같은 "두 신호" 위험이 생깁니다. 대기 줄은 사실상 한 줄 스텝 시퀀서라 rhythm-01 박자 시계(한 마디 무늬를 미리 보여 주는 재생 헤드)와 구조가 가까워집니다. 쌓기 게임은 장르에서 매우 흔해 UI가 닮아 보일 위험도 있음.

### 후보 C. 오므라드는 고리 (rhythm-01 탈락 후보 재검토)

- **한 문장 규칙**: 가장자리에서 오므라드는 고리가 가운데 원과 겹칠 때 톡 친다.
- **리듬 중심 방식**: 고리 반지름 = 박까지 남은 시간. 박 기준 ms 판정.
- **5~6세 적합성**: 중간~높음. 박 간격이 짧으면 고리 여러 개가 겹쳐 어느 것이 먼저인지 읽기 어려움.
- **아트·구현**: 매우 단순, 낮음.
- **위험**: 동시에 보이는 고리 수만큼 신호가 늘어남. 한 번에 1~2개만 보여서 무늬 암기가 약함(F3 약화). 원 가운데 고정 화면이라 rhythm-01(원 궤도)과 화면 인상이 닮음. 장르 표준 판정 UI와 닮아 보일 위험이 후보 중 가장 큼(rhythm-01 1-0 위험 R5와 같은 이유).

### 후보 D. 떨어지는 공 북 레인 (rhythm-01 탈락 후보 재검토)

- **한 문장 규칙**: 위에서 떨어지는 공들이 아래 북에 닿을 때 톡 친다.
- **리듬 중심 방식**: 낙하 거리 = 시간. 여러 공이 줄지어 내려옴(악보처럼 간격 = 리듬).
- **5~6세 적합성**: 높음. 판독 거리 넉넉(세로 화면).
- **아트·구현**: 매우 단순, 가장 낮음.
- **위험**: **runner-01 화면 구조와 겹침.** "고정된 지점으로 일정 속도로 다가오는 단서 줄"은 runner-01(장애물이 플레이어 쪽으로 흘러옴)을 90° 돌린 것과 같습니다(rhythm-01 1-0도 같은 이유로 탈락). 장르 표준 형태라 차별점이 사운드뿐. 줄지어 오는 공이 여러 개라 신호 수도 많음.

### 후보 E. 줄넘기 (rhythm-01 탈락 후보 재검토)

- **한 문장 규칙**: 빙글 도는 줄이 발밑에 올 때 톡 쳐서 뛰어넘고, 걸리면 다시.
- **리듬 중심 방식**: 줄이 바닥을 지나는 순간 = 박. 판정은 충돌 여부(점프 물리).
- **5~6세 적합성**: 매우 높음(현실 놀이).
- **아트·구현**: 단순, 낮음(점프 물리 재사용).
- **위험**: **runner-01과 조작이 겹침**(탭 = 내가 점프해 위험물을 넘음, 판정도 공간 충돌). 도는 줄은 원을 그리는 회전이라 rhythm-01·orbit-dodge의 회전 인상과도 닮음. 줄 주기가 바뀌면 미리 보이지 않아 억울한 실패, 일정하면 금방 지루함. 박 정확도(F5) 판정을 살리기 어려움.

### 예선 탈락 (표에 넣지 않음)

- **한 줄 스텝 시퀀서**(불빛 커서가 8칸 줄을 지나며 표시 칸에서 탭): 한 마디 무늬를 보여 주고 재생 헤드가 그 위를 도는 구조가 rhythm-01 박자 시계를 직선으로 편 것과 같음 → 겹침.
- **멈춰 놀이**(누르고 있으면 걷고, 술래가 돌아보는 박에 떼기): 홀드·떼기 2동작이고, 일찍 떼고 늦게 누르는 조심 전략으로도 깰 수 있어 리듬이 선택 사항이 됨. 5~6세는 정확히 떼기(멈추기)를 탭보다 어려워함 [추정].

**A의 겹침 판정 요지**
- runner-01: runner는 "화면이 흐르고 내가 뛰어 위험물을 피함". A는 "화면이 고정이고 내가 공을 쳐 올림". 조작의 대상(내 몸 / 공)과 실패 원인(부딪힘 / 떨어뜨림)이 다르고 카메라 이동이 없습니다. 공의 포물선이 점프 궤적과 모양이 닮은 것은 연출 수준이고, 높이를 아이가 정하지 않습니다.
- rhythm-01: 궤도 위를 도는 것도, 별 표식도, 마디 단위 무늬를 미리 펼쳐 보이는 것도 없습니다. 새 기믹은 **게임이 먼저 쳐 보이는 보여 주기 마디로 가르치지 않고**, 레벨 밖 그림 카드 + 안전한 첫 등장(받침 쉼 직후, 6-2)으로 가르칩니다. 콜앤리스폰스 구조를 쓰지 않습니다.
- orbit-dodge: 회피·방향 전환·궤도가 없습니다.
- 주의할 이웃: rhythm-01이 버린 D(떨어지는 공 북 레인)와 "공이 북에 닿을 때 친다"는 단서가 같습니다. 차이는 ① 공이 **하나뿐이고 계속 살아 있음**(내가 친 공이 돌아옴, 원인과 결과) ② **스크롤·줄지은 노트가 없음** ③ 리듬이 공간 간격이 아니라 **튀는 높이**로 표현됨. 1-1에서 art-director는 공이 여러 개 줄지어 내려오는 그림(레인처럼 보이는 배치)을 만들지 않습니다. 두 공 기믹(6절 G5)도 공 2개가 각자 튀는 모습이지 줄지어 내려오지 않습니다.

## 3. 선정 코어: A "통통 공받기"

### 3-1. 선정 근거

1. **신호가 가장 적은 코어입니다.** 판정 대상 = 공 하나, 별도의 차례 신호 없음. rhythm-01 round-1의 최대 문제(두 신호가 같은 순간 다른 행동을 가리킴, M1)가 구조적으로 생기기 어렵습니다(11절).
2. **놀이 그 자체라 글이 필요 없습니다.** 공 떨어뜨리지 않기는 5~6세가 이미 아는 규칙이고, 실패 원인이 물리적으로 보입니다.
3. **높이 = 시간이 리듬을 그림으로 보여 줍니다.** 긴 통·짧은 통이 긴 음·짧은 음과 바로 짝지어져 리듬이 판정의 중심이 됩니다(F5). 아이 음악 교육의 "긴 소리·짧은 소리"와 같은 단위입니다.
4. **판정을 눈에 보이는 접촉에 둘 수 있습니다.** 튀는 공은 박자 맞추기에서 깜빡이는 빛보다 훨씬 안정적인 시각 단서이고, 소리 메트로놈에 가까운 정확도를 낸다는 연구가 있습니다 [문헌: 성인 대상]. 그래서 판정을 화면 시계로 두고 소리는 맞추는 대상이 아닌 보상으로 쓰면, 블루투스 같은 큰 오디오 지연이 클리어를 막지 않게 할 수 있습니다(4-4).
5. **10레벨 제약을 감당합니다.** 공 하나하나가 독립 판정이라 클리어율 ≈ (공 하나 성공률)^(공 수)로 곡선을 잘게 조절할 수 있고, 기믹 어휘가 8개 + 예비로 레벨당 1개 이하 규칙을 지키며 10레벨을 채웁니다(6·7절).
6. 아트·구현이 가장 단순한 축이고, rhythm-01의 판정 코드 구조(가장 이른 미처리 대상 하나만 봄, 놓침 구역, 무시 구역)를 그대로 옮길 수 있습니다.

### 3-2. 규칙 정의 (1-1 기획의 출발점)

- 화면 아래 가운데에 북(받침) 하나. 공 하나가 북 위에서 튑니다. 화면은 움직이지 않습니다.
- **공의 다음 높이는 레벨 데이터가 정합니다.** 아이는 높이를 고르지 않고 "언제"만 맞춥니다. 접촉 시각은 항상 박 격자(4분·8분, 레벨 4부터 점4분 간격) 위.
- **판정**: 공이 북에 닿는 시각(접촉 시각) 근처에 탭 → 공이 정해진 높이로 튀어 오르고 북 소리. 등급(딱/좋아/통과)은 빛·소리 크기로만 구분, 살아남는 조건은 "통과" 하나.
- **실패**: 통과 창 끝까지 탭이 없으면 공이 북 옆으로 떨어짐("늦음"). 통과 창 바로 앞 놓침 구역 안의 탭은 헛스윙 연출 후 공이 떨어짐("일찍"). 그보다 이른 탭은 북이 톡 올라갔다 제자리로 돌아올 뿐 판정에 영향 없음(무시).
- **받침 쉼(카운트인·숨 고르기)**: 공이 북 위에 앉아 박마다 작게 까딱이고 똑딱 소리가 남(판정 없음, 탭은 무시). 쉼이 끝나면 **게임이 공을 스스로 띄움**(자동 토스, 판정 없음). 레벨 시작·재시작·연습 체크포인트가 모두 이 모습입니다.
- **한 접촉은 탭 하나만 씀.** 공 두 개(G5)일 때도 "아직 안 친 가장 이른 접촉 하나"만 봅니다(rhythm-01 `judgeAttempt`와 같은 순서).
- **진행도**: 화면 위 막대 = 처리한 접촉 수 / 전체 접촉 수(쉼에서 가짜 진행 없음). 최고 기록 점, 시도 횟수는 점 그림.
- 보여 주기 마디·차례 신호·북채 같은 시범 장치는 **쓰지 않습니다**(rhythm-01 겹침 회피 + 신호 최소화).

### 4-4. 판정 시계: 화면 기준 (rhythm-01과 다른 점)

- **판정 기준 = 화면에 보이는 접촉 시각.** 게임 시계 하나가 공 위치·접촉 시각을 정하고, 탭 시각은 `pointerdown`의 `event.timeStamp`로 같은 시계에 놓습니다. 남는 늦은 쪽 오차(터치 → 이벤트, 화면 표시 지연)는 상수 `visual_comp_ms`(초기값 **40 ms [추정]**: 터치 약 10~40 ms + 화면 1~2프레임)로 한 번만 빼고, QA가 실기기에서 잽니다.
- **소리는 맞추는 대상이 아니라 결과.** 곡은 오디오 시계로 예약하되, 자동 지연(`outputLatency + baseLatency`, 이중 보정 금지 insights 구현·성능 2번째 줄)만큼 앞당겨 화면 접촉과 들리는 박이 맞게 합니다. 탭 소리는 `pointerdown` 처리 안에서 바로 재생.
- 이렇게 하면 **블루투스(+120~+220 ms [rhythm-01 추정])에서 곡이 화면보다 늦게 들려도, 공을 보고 치는 아이는 클리어할 수 있습니다.** rhythm-01은 판정을 오디오 시계에 두어서 보정하지 않은 블루투스에서 모든 레벨 첫 클리어 중앙값이 200(상한)이었습니다(20-balance 8-3).
- 남는 위험: 소리에 맞춰 치는 아이는 블루투스에서 늦게 칩니다. 그래서 rhythm-01의 **보호자 보정(설정 길게 누르기 → 어른이 8번 × 2회)**은 "곡을 화면에 맞추는" 용도로 가져오되, 클리어의 전제 조건이 아님을 분명히 합니다(insights 구현·성능 3번째 줄). 보정 화면 그림은 박에 맞춰 움직이지 않음(같은 줄). 플레이 중 탭으로 오프셋을 자동으로 바꾸지 않음.
- 근거: 튀는 공의 박자 맞추기 변동성이 소리 메트로놈과 크게 다르지 않고, 깜빡이는 빛보다는 훨씬 안정적이라는 연구 [문헌, 성인 대상]. 5~6세에서도 같은지는 확인되지 않음 → 위험 K3.

### 5-2. 높이 = 시간 (공 궤적)

- 공의 높이를 진짜 중력으로 두면 높이가 시간의 제곱에 비례해 2박 통이 1박 통의 4배, 반박 통이 1/4이 됩니다. 반박은 안 보이고 4박은 화면을 한참 벗어납니다.
- 그래서 **꼭짓점 높이 H = c × 통 길이(초)** (직선 비례), 궤적은 포물선 모양 y(t) = 4H·s(1−s), s = 경과/통 길이로 둡니다 [추정].
  - 이렇게 하면 **북에 닿는 순간의 공 속도 = 4c로 모든 통에서 같습니다.** runner-01의 "속도 일정 → 거리 = 시간"처럼, 마지막 접근 모습이 늘 같아 치는 감각이 한결같습니다. 진짜 중력이면 긴 통일수록 빨리 떨어져 타이밍이 흔들림.
  - c는 레벨 사이에서도 고정 권장(빠른 레벨은 같은 1박도 조금 낮게 튐).
- 초안: **c = 0.5 × 놀이 높이(북 윗면 ~ 화면 위 안전선)/s**.

### 7-2. 요청자 지시 제약을 이 코어가 감당하는가

제약: 레벨 10 = L1~L3 σ70 첫 클리어 **연속 중앙값** m̃ = ln0.5/ln(1−p)의 기하 평균 배율 r = (m̃3/m̃1)^½로 외삽한 T = m̃3·r³ ±20 %, 모든 레벨 30회 이하, 직전 2배 이하, L3~L10 엄격 단조, L1 10회 이내.

- **감당 가능(판정).** 이유:
  1. 접촉이 서로 독립이라 p ≈ q^N(q = 접촉 하나 성공률, N = 접촉 수)으로 접촉 1개 단위로 m̃를 조금씩 옮길 수 있습니다. 예: 통과 250 ms(L10)에서 q ≈ [Φ(135/70) − Φ(−115/70)] × 0.97 ≈ 0.895, m̃ = 13.7이 되는 p ≈ 0.049 → N ≈ 27. 7-1 표 범위 안입니다(헛탭·짧은 통 손해를 넣으면 N은 더 작아짐).
  2. insights(난이도 2번째 줄)대로, 곡선을 고칠 때 새 기믹·BPM·판정 창은 두고 **통 순서만 쉬운 것으로 바꾸거나 접촉 1~2개를 빼면** 카드·곡 길이를 그대로 둔 채 맞출 수 있습니다(받침 쉼 마디로 바꾸면 곡 길이도 그대로).
- **L1~L3 배율 r의 권장 범위: 1.3 ~ 1.65.**
  - 위 한계: T × 1.2 ≤ 30이어야 L10이 30회 한도와 동시에 맞음 → T = m̃1·r⁵ ≤ 25. m̃1 = 1.9이면 r ≤ 1.67, m̃1 = 2.5이면 r ≤ 1.58.
  - 아래 한계: r이 1.25보다 작으면 L3~L10 7단계의 평균 배율 r^(3/7)이 1.10 밑이라 엄격 단조를 지키기 빠듯함.
  - 예: m̃ 1.9 / 2.8 / 4.2 → r 1.487 → T 13.8 → L10 목표 11.0~16.6. rhythm-01 round-2(T 13.70)와 같은 규모.
- L4~L9는 L3과 T 사이 등비 기준선(배율 (T/m̃3)^(1/7))을 따라 나눔. 직전 2배 한도는 기준선 배율이 약 1.2라 여유 큼.
- **봇이 못 보는 난이도**: σ70 봇은 타이밍 흔들림만 모델링하고 "높이를 읽고 예측하는 부담"(짧아지는 통, 두 공)을 모릅니다. G4·G5·G6 레벨은 봇 m̃이 실제보다 낮게 나올 수 있으므로, balance-designer는 ① 그 레벨들에 첫 등장 손해 모델(예: 길이가 짧아지는 접촉에 σ를 키움 또는 첫 등장 접촉 놓침률 상향)을 넣거나 ② 접촉 수를 보수적으로 잡고 근거를 적습니다(위험 K2).
- 측정 원천: 시뮬레이터 전체 실행 하나(insights 난이도 1번째 줄). 정수 중앙값은 참고, 빌드 봇은 일치 확인용.

1. 화면: 북·공·그림자·구름·진행도 막대, 가로·세로 배치, 놀이 높이 정의. 기본 도형·평면 색. 공이 줄지어 내려오는 그림 금지.
