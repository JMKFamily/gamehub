## 1. 설계 의도

1. **보이는 것은 공 하나, 맞추는 것은 "공이 북에 닿는 순간" 하나.** 차례 신호·시범 장치는 두지 않습니다. 화면의 다른 신호(받침 쉼 까딱·똑딱, 자동 토스, 착지, L1 손가락)는 모두 "치지 않아도 되는 때"이고, 그 시각이 어떤 접촉의 위험 구간과도 겹치지 않음을 검증기 S1~S5로 확인합니다.
2. **높이 = 다음 박까지 시간.** 무늬 암기의 중심은 높이의 대비(긴 통·짧은 통)입니다. 레벨마다 "통 통 큰통—", "점 통·점 통·통", "큰통— 통통 통"처럼 **높이 순서로 된 짧은 무늬**를 되풀이합니다(9-1).
3. **곡선은 접촉 수와 무늬로 만든다.** 레벨당 새 기믹은 1개 이하, BPM은 +2씩, 판정 폭은 직전의 94 % 이상으로 천천히 좁힙니다. 곡선 조정은 insights대로 새 기믹·BPM·판정 창을 두고 무늬만 쉬운 기존 무늬로 바꾸거나 1박 통 접촉을 넣고 빼서 했습니다(11절).
4. **실패 비용은 약 1.1 s.** 실패 → 다음 시도 첫 프레임 1.1 s 자동, 확인 버튼·결과 화면 없음(insights runner-01). 다시 첫 판정 접촉까지 3.6~4.1 s.

## 2. rhythm-01과의 구분 (오케스트레이터 추가 지시)

판정 순간("공이 무엇에 닿을 때 탭")만 보면 rhythm-01(궤도를 도는 공이 별에 닿을 때 탭)과 닮아 보일 수 있습니다. 이 게임의 핵심은 다른 데 있습니다.

| 축 | rhythm-01 | rhythm-02 (이 문서) |
|---|---|---|
| 몸으로 느끼는 감각 | 원을 따라 도는 **가로 회전**, 별 위치 = 박 | **세로 튐**. 공이 높이 뜨면 오래, 낮으면 금방 돌아옴. **높이 = 다음 박까지 시간** |
| 리듬을 미리 보는 방법 | 한 마디 무늬를 궤도 위 별로 펼쳐 보여 줌 + 보여 주기 마디(북채가 먼저 침) | 미리 펼치지 않음. 내가 쳐 올린 공의 높이를 눈으로 따라가며 다음 박을 앎. 무늬는 높이 순서로 외움 |
| 화면 요소 | 궤도·진한/흐린 별·북채·점선 궤도 | 북 1개·공 1개(L6부터 가끔 2개)·그림자·구름. **궤도·별·보여 주기 마디·북채 없음** |
| 가르치는 법 | 콜앤리스폰스(게임이 먼저 쳐 보임) | 그림 카드 1장 + 받침 쉼 바로 뒤 안전한 첫 등장. 게임이 대신 치지 않음 |
| 실패 모습 | 별이 깨짐 | 공이 북 옆으로 떨어짐(늦음) / 헛스윙에 미끄러짐(일찍) |
| 판정 시계 | 오디오 시계 | 화면 시계(4-4) |

레벨 설계에서도 같은 높이만 반복하는 구간(L1 제외)을 길게 두지 않고, 모든 구절에 높이 대비(1박↔2박, 1.5박, 0.5박, 3·4박)가 들어가게 했습니다(V14: L4부터는 박마다 고르게 치면 실패 = 높이를 읽어야 함).

## 5. 공 궤적: 높이 = 시간

- **꼭짓점 H = c × 비행 길이(s)**, 궤적 y(t) = 4H·s(1−s), s = 경과/길이(놀이 높이 = 북 윗면 ~ 화면 위 안전선 대비). **c = 0.5 /s, 모든 레벨 고정.** 북에 닿는 속도 4c = 놀이 높이의 2배/s로 모든 통이 같아 마지막 접근 모습이 늘 같습니다(진짜 중력이면 긴 통일수록 빨리 떨어져 타이밍이 흔들림).
- **구름선 = 놀이 높이의 90 %.** 구름 통만 구름선을 넘어 구름 뒤로 숨고(그림자는 계속 커짐), 다른 통은 늘 구름선 아래(V12). 1-0의 100 % 대신 90 %로 둔 이유: L10(122 BPM) 구름 통 꼭짓점이 98 %라 100 %면 숨지 않아 카드("구름에 숨었다 내려와")와 달라짐.

| 통 (id) | 비행 길이 | L1 100 BPM 꼭짓점 | L10 122 BPM 꼭짓점 | 구름 뒤 숨는 시간 |
|---|---|---|---|---|
| 통통 반박 (half, G4·G7) | 0.5박 | (L5부터) 13 % (112 BPM) | 12 % | − |
| 통 1박 (tong, B1) | 1박 | 30 % | 25 % | − |
| 점 통 (dot, G3) | 1.5박 | (L4부터) 41 % (110) | 37 % | − |
| 큰 통 (big, G1) | 2박 | 58 % (104) | 49 % | − |
| 세 박 통 (three, R1) | 3박 | (L7) 78 % (116) | (L9) 75 % | − |
| 구름 통 (cloud, G2) | 4박 | (L3) 111 % (108) | 98 % | L3 0.97 s · L10 0.57 s (≤ 1.0 s, K9) |

- 놀이 높이 400 px(360×640 세로)이면 반박 꼭짓점 약 50 px, 공 렌더 지름 **24 px 이상**(카드 속 16 px 이상, 렌더 px로 잼). 접촉 속도 약 800 px/s.
- 빌드는 `judge.mjs ballsAt(L, t, bal)`로 공 높이·상태(seated/up/down)를 얻어 그립니다(시뮬레이터 검사 V11·V12와 같은 함수).

## 6. 받침 쉼·자동 토스·재시작

### 6-1. 구절 구조 (레벨 = 구절 2~4개)

```
받침 쉼(공이 북 위에 앉음, 박마다 까딱 + 똑딱) → 자동 토스(게임이 띄움, 마디 첫 박) → 접촉들(아이가 침) → 착지(마지막에 친 공이 내려와 앉음) → 다음 받침 쉼 …
```

- 받침 쉼: 최소 4박, 토스가 **마디 첫 박**에 오도록 늘림(4~7박). 똑딱은 **정박에만**. 쉼 동안 탭은 무시(북만 톡).
- 자동 토스: 판정 없음. 토스 비행 길이 ≥ 1박(토스를 따라 친 탭이 다음 접촉 놓침 구역보다 ≥ 150 ms 앞 → 무시, S2). 첫 구름 통·첫 세 박 통·첫 통통 앞 큰 통은 **토스로** 던짐(받침 쉼 바로 뒤 안전한 첫 등장).
- 착지: 마지막 접촉을 친 공이 정해진 길이(1박, 두 공은 2박) 뒤 북 위에 앉음. 판정 없음. 착지를 따라 친 탭도 무시(S5).
- 두 공(G5): 공 2가 받침 쉼 동안 옆에서 굴러 들어와, 공 1 토스 1박 뒤에 토스됨. 두 공 모두 2박 비행으로 번갈아 닿음(서로 다른 공 접촉 간격 = 1박, 하나 올라갈 때 하나 내려옴, V11·S4). 착지 때 공 2는 굴러 나감.
- 연습 모드: **각 받침 쉼이 자동 체크포인트**(공이 앉아 있는 안전한 지점, 앞에 위험 없음). 수동 체크포인트 버튼 없음(insights runner-01). 부활 시간 = 일반 재시작 1.1 s.

### 6-2. 실패 → 재시작 1.1 s 배분 (`balance.json restart`)

| 구간 (실패 판정 시각 기준) | 내용 |
|---|---|
| 0 ~ 0.08 s | 곡 멈춤(짧은 페이드) |
| 0 ~ 0.45 s | 공 떨어짐 연출: 늦음 = 북 옆으로 굴러 떨어짐, 일찍 = 북이 내려오는 중에 닿아 미끄러짐. 실패음은 아이 탭보다 작게 |
| 0.45 ~ 0.85 s | 정지, 진행도 막대에 최고 기록 점 |
| 0.85 ~ 1.10 s | 공이 북 위에 다시 나타남(앉은 모습) |
| 1.10 s | 레벨 시간 0 = 첫 똑딱. **"실패 → 다음 시도 첫 프레임" = 1.1 s(허용 0.94~1.20), 자동, 확인 버튼 없음** |

- 실패 판정 시각: 늦음 = 통과 창 끝, 일찍 = 그 탭 시각. 오디오 선행 대기는 1.1 s 안에 포함(insights runner-01 구현 마지막 줄).
- 재시작 위치 = 레벨 처음. **실패 → 다음 판정 접촉 = 1.1 s + 첫 접촉 시각 = L1 4.10 s … L10 3.56 s** (모두 ≤ 6 s, V10).
- 결과 화면은 클리어 때만. 첫 실패에만 ↻ 그림 안내(lore·dev, insights).

## 11. 곡선을 맞춘 과정 (insights 적용 기록)
