## 1. 아트 방향

**한 줄**: 밝은 단색 바탕, 아래 가운데 **납작한 파란 북 하나**, 그 위에서 **붉은 공 하나가 위아래로만** 통통 튄다. 평면 단색 면 + 짙은 잉크 외곽선, 그라데이션·발광·질감·투명도 없음.

레퍼런스 키워드(특정 게임이 아닌 일반 사물): 놀이터 고무공, 장난감 북(옆에서 본 모양), 색종이 구름, 그림책의 "통 통" 의성어 그림.

- 사진 한 장으로 "공이 내려오면 북으로 친다"가 읽혀야 합니다. 움직이는 것은 공(과 두 공 레벨의 둘째 공)뿐이고, 화면은 고정입니다(스크롤·카메라 이동 0).
- 세계관 화풍·캐릭터 없음. 공·북에 얼굴·이름·성격을 주지 않습니다. 장식은 레벨 바탕색과 **정지 실루엣(바탕보다 살짝 진한 한 가지 색, 기본 도형 3개 이하)**뿐이고, 다 지워도 플레이가 그대로 성립합니다.
- **하지 않는 것(1-0 2-3·10절, 오케스트레이터 지시)**: 공이 여러 개 줄지어 내려오는 그림(레인처럼 보이는 배치), 스크롤 배경(runner-01), 궤도·별·북채·보여 주기 마디 표시(rhythm-01), 원형 판정 고리·오므라드는 고리, 판정 글자 팝업, 음표 모양 아이콘. 자세한 구분은 10절.

## 4. 화면 구성 (`assets/layout.json`, 계산 `tools/art/layout.mjs`)

### 4-1. 놀이 높이 정의

- **공 높이 h** = 공 아랫점과 북 가죽 윗면 사이 거리(px). h = 0이 접촉.
- **놀이 높이 Hp** = `(skinY − (safeTop + 8) − d − 6) / 1.2`. 즉 "100 BPM 구름 통(4박 2.4 s, 꼭짓점 1.2·Hp)의 공 윗점이 화면 위 여백 안에 들어가는 가장 큰 높이"입니다. balance의 높이 식 `h_apex = c × 통 길이`, `c = 0.5·Hp/s`(00-benchmark 5-2, balance.json `height.c_play_height_per_s`)의 기준 길이가 이 Hp입니다.
- **구름 아랫선** = h = 0.9·Hp 높이(공 아랫점이 이 선 위면 공 전체가 구름 뒤). balance.json `cloud_line_ratio` 0.9와 같음(작성 중 balance가 1.0 → 0.9로 맞춤, 13절 X2).
- 공 지름 d = `round(clamp(0.078·S, 24, 44))`, S = min(W, H). 북 = 3.2d × 0.95d.
- 세로: 북 가죽 y = 0.76·H, 그 아래 전부 바닥(엄지가 닿는 자리). 가로: 바닥 높이 max(40, 0.11·H), 북은 바닥 위.
- 구름 너비 = min(2.6·구름 높이, 0.62·W), 북 가운데 위. **HUD는 구름 위에 그립니다**(구름 윗부분이 진행도 막대 뒤로 가도 됨, 공이 보이는 구간과 HUD는 겹치지 않음).

## 5. 움직임과 반응

### 5-1. 공 궤적·그림자

- 공 위치는 balance의 화면 시계 함수(`judge.mjs ballsAt()`)를 그대로 따릅니다. art가 정하는 것: 공은 **x 고정**(두 공이면 북 중심 ±0.78d), 회전 없음, 꼬리 없음.
- 접촉 순간 납작 0.85(세로)·1/0.85(가로) 60 ms, 판정 등급별 납작 정도는 6절.
- 그림자는 늘 보임(구름 뒤에 있을 때도). 구름 통에서 내려올수록 커지는 것이 "곧 내려온다" 신호(G2).

### 5-2. 탭 반응 "북 톡" (판정과 무관하게 매 탭)

- `pointerdown` 처리 안에서 바로: 북 전체가 0.22d 올라갔다(50 ms, ease-out) 내려옴(70 ms, ease-in) = 120 ms(balance `drum_pop_ms`).
- 헛탭·무시되는 탭(받침 쉼, 이른 탭): 이 움직임 + 아주 작은 톡(`tap_empty`, −30 dB) 하나. 물결·빛 없음.
- 받침 쉼: 공이 가죽 위에 앉아 **박마다 작게 까딱**(납작 0.92, 100 ms) + 똑딱(정박만). 쉼 끝 자동 토스는 **공이 스스로 뜸**(북은 움직이지 않음) — 북이 움직이면 "내가 쳐야 했나" 신호가 되므로. 토스 소리 없음.
- 두 공 레벨: 둘째 공은 받침 쉼 동안 바닥 오른쪽에서 굴러 들어와 북 오른쪽 자리에 앉고(balance `second_ball_enter`), 마지막 착지 뒤 오른쪽으로 굴러 나감. 두 공이 같은 높이로 같은 순간 내려오는 그림 없음(카드 G5도 높이를 다르게 그림).

### 5-3. L1 튜토리얼 손가락 (insights 5~6세 2번째 줄, runner-01 "플레이어 기준 위치")

- 레벨 1 첫 접촉 1회만(balance `tutorial_finger.contact_index 0`).
- 위치: **북 기준**. 손끝 x = 북 오른쪽 끝 + 0.7d, 손끝 y = 바닥 윗선. 높이 1.5d. 화면 고정 위치 아님.
- 시간: 자동 토스 순간에 나타남(0.15 s 커지며) → **누름 시작 = 접촉 − 0.2박**(100 BPM에서 −120 ms) → 누름 100 ms(양옆 선 2개) → 접촉 + 300 ms 뒤 사라짐.
- **누름 시작이 통과 창 안**: L1 통과 창 이른 쪽 −150 ms(levels/01 `judge.pass_early_ms`) < −120 ms ✓. 규칙: 누름 시작 ≥ 접촉 − (pass_early − 20 ms). balance가 L1 BPM·창을 바꾸면 이 식으로 다시 확인(`layout.json` `finger`).
- 손가락이 보이는 동안 다른 신호 없음(차례 신호·시범 없음).

- **곡 음의 시작은 정박에만**: 플레이 마디는 2분 격자(마디 1박·3박)에만 똑(`tick_a`)·베이스·멜로디가 시작, **받침 쉼 마디는 똑 딱 똑 딱 4번**(`tick_a`·`tick_b`). 반박·점 리듬 자리에는 곡 음이 시작하지 않아 **엇박을 채우는 것은 아이 탭뿐**입니다(rhythm-01 셰이커 교훈).
- 꼭짓점·구름에 닿는 소리, 자동 토스 소리 없음(박 사이 소리는 헛탭을 부름).
- 곡 위치 = 플레이 위치(레벨 시간 0 = 첫 똑딱). 실패하면 곡도 처음(또는 체크포인트)부터(insights runner-01).
- **곡 음 시작 규칙 검사**: 곡 음이 어떤 접촉의 놓침 구역 [c − pass_early − miss_zone, c − pass_early)에 들지 않음(같은 시각의 다른 접촉이 있으면 제외). balance 1-1 레벨 파일 10개(`levels/*.json`, 레벨별 judge 값 사용, 놓침 구역 200 ms)에 적용 → **위반 0**. 규칙 사례 6개 + 반례 2개(점 통을 둘째 박에서 시작, 점 통 뒤 반박)도 기대대로 걸러냄. 반례 = balance 배치 규칙 후보(13절 X5).

### 10-2. 핵심 그림: 세로 튐 = 높이가 시간

- 북이 화면 **아래** 바닥 위에 놓이고(rhythm-01은 화면 가운데 원 중심), 공이 북 **위**로 떨어집니다(rhythm-01은 공이 북 둘레를 돎).
