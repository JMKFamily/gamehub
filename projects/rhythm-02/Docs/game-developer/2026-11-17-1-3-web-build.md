## 인사이트 후보
- 판정이 "탭 목록 → 결과" 순수 함수면 빌드는 탭마다 같은 함수를 전체 탭 목록으로 다시 부르기만 하면 되고(접촉 수십 개라 비용 무시), 빌드 판정 = 시뮬레이터 판정이 구조적으로 보장됨. 늦음 실패만 고정 스텝 틱이 판정 시각을 지났는지로 확인. 근거: `games/rhythm-02/js/core.js`, selfcheck-sim C1(2만 회 불일치 0). 적용: game-developer(리듬 게임 전반).
- 화면 시계 판정에서 늦음 실패 선언을 2프레임(34 ms) 늦추면 프레임 정렬로 늦게 배달되는 탭 이벤트를 놓치지 않음. 실패 시각은 판정 값 그대로 두면 재시작 시간에는 영향 없음. 근거: DEV_NOTES 2절. 적용: game-developer.
- 6배 스로틀링 시작 직후 1% low 측정은 "앞 화면이 다 그려진 뒤" 시작해야 함: 타이틀 탭 직후 바로 재면 레벨 선택 그림 디코드가 섞여 33~100 ms 튐으로 잘못 나옴(1.5 s 뒤 재면 59.5 fps). 테마 CSS 변수 바꾸기도 플레이 시작에서 빼 멈춤·결과 때로 미룸. 근거: selfcheck-browser 5절. 적용: qa-engineer·game-developer.
- 미리 합성: 오디오 잠금 해제 때 모든 소리를 소리 0 버스로 한 번 만들어 첫 예약 튐을 줄임(공용 post 필터는 그 버스에 붙이지 않게 주의). 근거: `js/audio.js unlock`. 적용: game-developer.
