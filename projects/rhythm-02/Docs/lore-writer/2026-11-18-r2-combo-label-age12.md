# r2 콤보 라벨 + 12세 대상 반영

- 날짜: 2026-11-18
- 역할: lore-writer
- 프로젝트: rhythm-02
- 단계: round-2 (빌드 게시 뒤 추가 지시 — art 콤보 연출·balance 12세 재조정 후속)

## 요청 받은 일
오케스트레이터가 다음 두 가지를 요청했습니다.
- art 콤보 연출 보고서의 "lore에 넘길 것" 처리: `combo_label` 키를 만들고, 라벨은 aria-hidden, `aria_combo` meter는 큰 숫자 자리로 옮김.
- balance 12세 재조정 "lore" 항목 처리: 레벨 길이·접촉 수 숫자 갱신.

근거는 criteria 대상 연령 결정 14(12세, 12세 어휘 가능, 글 없이 시작하는 튜토리얼 유지)와 게임 감각 "파격적인 콤보 연출"(131aa6a)입니다.

## 한 일
1. `strings.json`에 `combo_label` { ko "콤보", en "COMBO" }을 추가했습니다(`aria_combo` 바로 뒤, `_meta` 날짜 갱신).
   - 일반 낱말이고 원작 글자 디자인과 관계없습니다. KR 2자 / EN 1단어라 플레이 중 한도 안입니다.
   - 키는 89개에서 90개가 됐고, 기존 문구는 바꾸지 않았습니다.
2. 10-lore에서 옛 "점 10칸 / HUD 칸 줄" 설명을 새 연출로 바꿨습니다.
   - 새 연출: 위쪽 가운데 큰 숫자 + 라벨 [표지] 콤보 [단계 칸 4] + 화면 조각 10·20·30·50, 끊김 0.25 s.
   - 고친 곳: 확정값 표, 3절 콤보·최고 콤보 표지 행(금빛 네모 0~2개 → 0~5개), 5절 콤보·지붕 참기, 7-4(15개, `combo_label` 행·`aria_combo` 자리), 7-8 끝 줄, 7-10 최고 콤보 행, 8-1 비교 행, 10절 스토어 긴 설명 KR·EN 한 줄씩, 합계 90.
3. 6절 접근성 규칙을 바꿨습니다.
   - 4·5: meter `aria_combo`는 큰 숫자 자리 요소에 붙이고, valuetext는 숫자만 두며 `aria-live`는 쓰지 않습니다.
   - 라벨·단계 칸·조각은 `aria-hidden`이라 "콤보"가 겹쳐 읽히지 않습니다.
   - 11: 플레이 화면 트리 확인 목록에 "라벨 글은 트리에 없음"을 넣었습니다.
   - 12: 키 수를 90으로 고쳤습니다.
4. 12세 대상을 반영했습니다.
   - 머리에 "대상 연령" 줄을 넣었습니다: 12세 어휘 허용, 글 없는 튜토리얼과 문구 한도 유지, 본문의 "5~6세" 근거는 당시 기록으로 읽음.
   - 이 줄에 레벨 길이 약 31~49 s, 접촉 27~56(hit 27~53 + 지붕 참기)을 참고 값으로 적었습니다. 원본은 20-balance 19절입니다.
   - 10-lore 본문과 strings에는 원래 레벨 길이·접촉 수를 적은 곳이 없어서 따로 고칠 숫자는 없었습니다.
   - 유아적인 말이 있는지 봤지만 모두 쉬운 말이라 바꾸지 않았습니다. 대체 글 "이어서 잘한 수"와 판정 이름 "딱이야/좋아/됐어"도 그대로입니다.
5. 7-9 검사를 고쳤습니다.
   - ⑤ 금지어: `combo_label`만 콤보·combo를 허용합니다.
   - ⑩ 새 항목: `combo_label`이 ★인지, 길이가 맞는지, `layout.json combo.label.text_key`와 같은지 봅니다.

## 다른 팀에 줄 인사이트
- [rhythm-02·2026-11-18] 화면 라벨("콤보")과 meter 대체 글을 함께 둘 때 규칙이 있습니다.
  - 라벨은 `aria-hidden`으로 두고, meter는 큰 숫자 자리 요소 하나에만 붙입니다. 그래야 "콤보, 이어서 잘한 수, 7"처럼 두 번 읽히지 않습니다.
  - meter는 상호작용 요소가 아니어서 WCAG 2.5.3(Label in Name)에 걸리지 않습니다. 그래서 대상 연령을 올려도 이미 쉬운 대체 글은 바꾸지 않아도 됩니다.
  - 금지어 검사에 "콤보"가 있던 프로젝트는 라벨 키 하나만 예외로 둡니다.
