# 00. 벤치마크: 원터치 리듬 오토러너 플랫포머

- 레퍼런스: Geometry Dash (RobTop Games, 2013~, iOS/Android/Steam)
- 목적: 장르, 조작, 핵심 루프, 수치 감각, 진행 구조만 추출합니다. 원작의 이름, 캐릭터, 아트, 음악, 레벨 배치, UI 디자인, 텍스트는 가져오지 않습니다 (`harness/PIPELINE.md` 원본 보호 규칙).
- 단위 약속: 이 문서에서 **1타일 = 플레이어 기본 몸체 한 변**입니다. 원작 에디터 그리드 1칸(내부 30 유닛)과 같습니다. 시간은 초(s), 속도는 타일/초(t/s)로 씁니다.
- 표기: **[확인]** 공개 자료에 수치가 있음, **[추정]** 커뮤니티 분석·플레이 관찰을 근거로 계산한 값. 추정치는 빌드 후 자동 플레이 지표로 다시 맞춥니다.

## 1. 한 줄 요약과 타깃 유저

**한 줄 요약**: 캐릭터는 일정한 속도로 오른쪽으로 계속 달리고, 플레이어는 화면 탭 하나로 점프 타이밍만 정합니다. 음악 박자에 맞춰 배치된 장애물을 통과하고, 한 번 닿으면 즉시 처음부터 다시 시작합니다.

**타깃 유저**
- 1차: 10~20대 모바일 캐주얼·미드코어. 짧은 시도를 많이 반복하며 "한 번만 더" 하는 걸 즐기는 유저. 리듬게임이나 고난도 플랫포머 플레이 영상을 즐겨 보는 층.
- 2차: 출퇴근이나 대기 시간에 세로 한 손이 아닌 **가로 양손 또는 한 손 엄지**로 1~5분씩 하는 유저.
- 동기: 숙달(같은 구간을 외워서 넘는 쾌감), 진행도 % 갱신, 클리어 인증.

## 2. 핵심 루프

| 단위 | 시간 | 루프 | 감정 곡선 |
|---|---|---|---|
| 초 단위 | 0.3~1 s | 장애물을 보고 → 박자에 맞춰 탭 → 착지·통과 | 긴장 → 해소. 박자와 점프가 맞을 때 "손맛" |
| 시도(판) 단위 | 2~90 s | 시작 → 구간 진행 → 사망 → 약 1 s 안에 자동 재시작 → 최고 진행도 % 갱신 | 실패해도 바로 재시도. 최고 기록 바가 조금씩 앞으로 나감 |
| 레벨 단위 | 10~60분 (수십~수백 회 시도) | 구간 암기 → 클리어 → 보상(재화·별) → 다음 레벨 해금 | 첫 클리어 순간이 가장 큰 보상 |
| 세션 단위 | 5~20분 | 한 레벨을 몇 % 더 밀거나, 연습 모드로 어려운 구간만 반복 | "오늘 50% 넘겼다" 같은 작은 목표 |

핵심은 **실패 비용이 거의 0**이라는 점입니다. 사망부터 다음 시도까지 1초 남짓이고, 메뉴나 확인 버튼이 없습니다.

## 3. 조작 방식과 입력 판정

| 항목 | 원작 방식 | 비고 |
|---|---|---|
| 입력 | 화면 아무 곳이나 탭/홀드 (PC는 클릭, 스페이스, 위 화살표) | 버튼이 1개뿐 |
| 탭 | 지면에 있을 때 누르면 고정 높이로 점프 | 점프 높이는 누른 시간과 상관없음 (가변 점프 없음) |
| 홀드 | 누르고 있으면 착지하는 순간 자동으로 다시 점프 | 사실상 "착지 시 입력 버퍼". 연속 점프 구간을 홀드로 넘음 |
| 공중 입력 | 지면 점프에는 쓰이지 않음. 공중 재점프 트리거에 닿은 상태에서 눌렀을 때만 반응 | 트리거는 "겹친 상태 + 새로 누름"으로 발동 [추정: 홀드만으로는 발동하지 않고 누르는 순간이 필요. 2.x 버전은 홀드 상태로 진입해도 발동하는 경우가 있어 버전별 차이 있음] |
| 코요테 타임 | 사실상 없음. 지면을 벗어나면 점프 불가 [추정] | 대신 판정 박스가 몸체 한 변 전체라서 모서리에 걸쳐도 지면으로 인정됨 |
| 입력 샘플링 | 1.x~2.1: 렌더 프레임마다 입력 처리. 2.2: 물리 240 tick/s, 입력을 프레임 사이에서도 반영하는 방향으로 개선 [확인: 커뮤니티 봇·모드 개발자 글] | 우리 빌드는 입력 타임스탬프를 물리 틱에 매핑 (7절) |
| 다른 이동 모드 | 비행(홀드 시 상승, 떼면 하강), 중력 반전 탭, 일정 각도 지그재그 등 | MVP에서는 지면 점프 모드만. 10절 참고 |

| 속도 단계: 느림 | 8.37 t/s | 기본의 0.81배 | [확인] 위키 | 8.4 t/s |

| 점프 수평 거리 (보통 속도) | **약 4.0~4.4 타일** | 속도 × 체공 | [추정] "보통 속도에서 바닥 가시 3개 연속을 한 번에 넘을 수 있고 4개는 어렵다"는 관찰과 일치 | 4.15 타일 |

| 최대 낙하 속도 | 약 26~30 t/s | - | [추정] 원작은 낙하 속도 상한이 있음. 정확값 미확인 | 28 t/s |
| 하강 중 중력 배율 | 1.0 (대칭 포물선) | - | [추정] 플레이 관찰상 상승·하강이 거의 대칭 | 1.0 |
| 몸체 회전 (연출) | 1회 점프당 180° | 0.40 s 동안 | [추정] 영상 관찰. 착지 시 90° 단위로 스냅 | 동일 (판정과 무관) |

밸런스 기획자 참고용 파생값 (보통 속도 10.4 t/s 기준):

| BPM | 1박 길이(s) | 1박 = 몇 타일 | 반박 = 몇 타일 |
|---|---|---|---|
| 120 | 0.500 | 5.20 | 2.60 |
| 128 | 0.469 | 4.88 | 2.44 |
| 140 | 0.429 | 4.46 | 2.23 |
| 150 | 0.400 | 4.16 | 2.08 |
| 160 | 0.375 | 3.90 | 1.95 |

- 체공 0.40 s는 150 BPM 한 박과 거의 같습니다. 즉 **연속 홀드 점프는 약 150 BPM 4분음표 간격**으로 반복됩니다. 레벨 BPM을 이 근처로 잡으면 "점프 = 박자"가 자연스럽게 맞습니다.
- 장애물 사이 최소 간격(착지 후 다시 점프할 여유) [추정 권장]: 점프 거리 + 1타일 이상 = 5.2타일 ≈ 0.5 s.

## 6. 레벨 구조, 난이도 곡선, 진행·보상

**레벨 구조 (원작 공식 레벨의 패턴)**
- 한 레벨 = 한 곡. 곡의 구조(도입, 빌드업, 드롭, 브리지, 마무리)에 맞춰 구간이 나뉩니다.
- 구간 길이는 약 8~16박. 구간마다 기믹이나 이동 모드가 바뀌고, 드롭에서 밀도와 속도가 올라갑니다.
- 레벨 안의 난이도는 단조 증가가 아니라 **톱니 모양**입니다. 어려운 구간 뒤에 쉬운 숨 고르기 구간(2~4박)이 옵니다.
- 새 기믹은 **안전한 첫 등장 → 단독 연습 → 다른 기믹과 조합** 순서로 나옵니다 [추정: 초기 공식 레벨들의 공통 패턴].

**레벨 간 난이도 곡선 (원작 초기 레벨 기준 관찰)**

| 순번 | 새로 배우는 것 | 속도 | 체감 시도 횟수 [추정] |
|---|---|---|---|
| 1 | 탭 점프, 블록 올라타기, 연속 장애물 | 보통 | 3~15회 |
| 2 | 발판 자동 점프, 공중 재점프 | 보통 | 10~30회 |
| 3 | 중력 반전, 비행 모드 | 보통~빠름 | 20~60회 |
| 4~ | 속도 변화, 크기 변경, 조합 | 빠름 이상 | 50회 이상 |

**진행·보상**
- 레벨별 최고 진행도 %(일반 모드, 연습 모드 따로) 저장.
- 레벨 안 숨겨진 수집품 3개. 경로 분기나 위험한 우회 루트 끝에 둠. 수집 후 그 시도에서 클리어해야 인정.
- 클리어 보상: 난이도별 별, 재화. 별과 재화로 외형(아이콘, 색) 해금.
- 연습 모드: 원하는 지점에 체크포인트를 찍고 거기서 재시작. 클리어로 인정되지 않음.
- 업적: 시도 횟수, 점프 횟수, 클리어 수 등 누적 지표.

## 7. 리텐션·수익화 장치

| 장치 | 원작 방식 | 효과 |
|---|---|---|
| 진행도 % | 시도마다 최고 기록 갱신 표시 | 실패해도 성장감 |
| 시도 횟수 표시 | 레벨 시작 시 "N번째 시도" 표시 | 끈기 자체가 콘텐츠. 클리어 시 자랑거리 |
| 외형 수집 | 아이콘·색·이펙트 해금 (게임 플레이 능력치 없음) | 장기 목표. 공정성 유지 |
| 유료 앱 + 무료 체험판 | 정식판 유료, 무료판은 레벨 일부 + 광고 | 일회성 결제 |
| 유저 제작 레벨 | 레벨 에디터와 온라인 공유 | 콘텐츠 무한 공급 (우리 MVP 범위 밖) |
| 일일·주간 레벨 | 정해진 레벨을 기간 한정 제공 | 매일 접속 이유 |

**우리 쪽 시사점**: 웹 무료 + Android 무료(광고 최소)로 시작합니다. 리텐션의 핵심은 % 바, 시도 횟수, 수집품입니다. 강제 전면 광고를 재시작 사이에 넣으면 "실패 비용 0" 루프가 깨지므로 금지합니다.

## 8. 사운드와 리듬의 역할

- 음악이 **레벨 설계의 박자 격자**입니다. 장애물은 박·반박 위치에 놓이고, 점프 입력이 비트와 겹칩니다.
- 음악은 플레이어 위치와 1:1로 묶여 있습니다. 사망하면 음악도 함께 끊기고 재시작 시 처음부터 다시 나옵니다. 따라서 **음악이 진행도 지표 역할**을 합니다 (익숙한 소절 = 이만큼 왔다).
- 효과음은 최소입니다. 사망음 1개, 수집음, 메뉴음 정도. 점프음은 기본적으로 없고, 음악 자체가 피드백입니다 [확인: 플레이 관찰].
- 시각 연출(배경 펄스, 색 전환)이 음악의 킥·드롭에 맞춰 리듬 체감을 강화합니다.
- 우리 게임: 음악·효과음은 전부 자체 제작이거나 라이선스가 명확한 것만 씁니다. 원작 곡과 유사한 곡은 금지합니다.

## 9. 모바일 웹 구현 시 주의점 (HTML5 캔버스 단일 파일 → Capacitor Android)

| 주제 | 위험 | 대응 |
|---|---|---|
| 입력 지연 | `click`은 300 ms 지연과 제스처 판별 지연이 있음. 스크롤·확대가 입력을 먹음 | `pointerdown`/`touchstart`만 쓰고 `{passive:false}` + `preventDefault()`. 캔버스와 body에 `touch-action:none`, `user-select:none`. 뷰포트에 `user-scalable=no` |
| 입력 타이밍 정밀도 | 렌더 프레임(16.7 ms)마다 입력을 처리하면 최대 1프레임 오차. 체공 0.40 s 기준으로 체감이 큼 | 입력 이벤트의 `event.timeStamp`를 기록하고, 고정 스텝 물리에서 그 시각에 해당하는 틱에 반영. 홀드 상태는 별도 플래그 |
| 프레임 독립 물리 | 60/90/120 Hz 화면과 프레임 드랍마다 점프 궤적이 달라지면 레벨이 기기마다 다르게 됨 | 240 Hz 고정 스텝 누적기(accumulator). 한 프레임당 최대 스텝 수를 제한(예: 0.1 s 분량)해 탭 전환 후 폭주 방지. 렌더는 보간. 같은 입력이면 같은 결과가 나오는 결정론 유지 (자동 플레이 검사에도 필요) |
| 오디오 동기화 | `<audio>` 태그는 시작 지연과 위치 오차가 큼. Android WebView 출력 지연이 수십~150 ms [추정] | Web Audio API 사용. 첫 탭에서 `AudioContext.resume()`. 게임 시계는 `audioContext.currentTime` 기준으로 잡고 물리 x 위치를 음악 시간에서 도출. `outputLatency`/`baseLatency`로 보정하고 설정에 수동 오프셋(±ms) 보정 슬라이더 제공 |
| 재시작 시 음악 | 디코딩을 매번 하면 재시작이 느려짐 | 곡을 한 번 `decodeAudioData`로 버퍼에 두고 재시작마다 새 `AudioBufferSourceNode`를 0 지점에서 시작 |
| 백그라운드 전환 | 탭 전환, 전화 수신 시 시간 점프 | `visibilitychange`에서 자동 일시정지, 복귀 시 카운트다운 |
| 성능·GC | 가비지 컬렉션 멈춤이 곧 즉사 원인 | 매 프레임 객체 생성 금지(풀링). `devicePixelRatio`를 최대 2로 제한. 화면 밖 장애물은 그리지 않음 |
| 화면 비율 | 기기마다 가로 길이가 달라 보이는 앞쪽 거리가 달라짐 | 세로 높이 기준으로 고정 타일 수(예: 세로 약 10타일)를 보여주고, 가로는 늘어나는 만큼 더 보여주되 플레이어 x 위치는 화면 왼쪽 약 30%에 고정 |
| Capacitor 래핑 | 상태바·내비게이션바, 화면 꺼짐, 회전 | 가로 고정, 몰입 모드 전체화면, 화면 켜짐 유지, 뒤로 가기 버튼은 일시정지로 매핑 |

## 10. 가져올 것 / 바꿀 것 / 가져오지 않을 것

| 구분 | 항목 | 내용 |
|---|---|---|
| 가져올 것 | 장르·조작 | 자동 수평 이동 + 원터치 고정 높이 점프 + 홀드 시 착지 자동 재점프 |
| 가져올 것 | 수치 감각 | 4절의 속도 단계 비율, 점프 높이 약 2.15타일, 체공 약 0.40 s, 겉모양보다 작은 즉사 판정 |
| 가져올 것 | 핵심 루프 | 즉사 → 1초 이내 자동 재시작, 진행도 % 바, 시도 횟수 |
| 가져올 것 | 레벨 철학 | 한 레벨 = 한 곡, 박자 격자 배치, 톱니형 난이도, 기믹 도입 3단계 |
| 가져올 것 | UX 패턴 | 연습 모드(체크포인트), 레벨당 수집품 3개 |
| 바꿀 것 | 재시작 속도 | 원작 약 1.0 s → 우리 ≤ 0.8 s |
| 바꿀 것 | 초반 난이도 | 1번 레벨은 원작보다 완만하게. 첫 10초는 실패할 수 없을 정도로 쉬운 튜토리얼 구간 |
| 바꿀 것 | 오디오 보정 | 모바일 웹 지연 때문에 입력·오디오 오프셋 보정 옵션을 처음부터 제공 |
| 바꿀 것 | 플랫폼 | 웹 우선, 세로 높이 기준 반응형 화면 |
| 바꿀 것 | 수익화 | 유료 앱 대신 무료. 재시작 사이 광고 금지 |
| 가져오지 않을 것 | 이름·텍스트 | 게임명, 레벨명, 기믹 이름, UI 문구 |
| 가져오지 않을 것 | 아트 | 정사각형 얼굴 캐릭터 디자인, 아이콘, 장애물 모양, 배경, UI 디자인 (아티스트가 새로 정의) |
| 가져오지 않을 것 | 음악·효과음 | 원작 곡, 원작에 쓰인 외부 곡, 사망음 등 전부 |
| 가져오지 않을 것 | 레벨 배치 | 원작 공식 레벨의 장애물 배열과 구간 구성 |
| 가져오지 않을 것 | 기타 | 유저 레벨 에디터·온라인 공유(범위 밖), 원작 고유 재화 체계 |

## 11. 첫 버전(MVP) 범위 제안

**목표**: 웹에서 "탭 → 점프 → 즉사 → 즉시 재시작" 루프의 손맛이 원작 수준인지 검증하고, 같은 빌드를 Capacitor로 Android 내부 테스트 트랙에 올립니다.

| 항목 | MVP 포함 | MVP 제외 (다음 버전) |
|---|---|---|
| 레벨 수 | **3개** (각 40~75 s, 한 곡씩) | 4번 이후, 일일 레벨 |
| 이동 모드 | 지면 점프 모드 1개 | 비행, 지그재그, 크기 변경 등 |
| 기믹 | G1 블록, G2·G3 바닥 즉사, G4 천장 즉사, G5 발판 자동 점프, G6 공중 재점프, G12 얇은 발판, G8 속도 변경(3번 레벨, 느림·보통·빠름만), G13 연출 | G7 중력 반전은 3번 레벨 마지막 구간에 1회 시험 도입 여부를 밸런스 기획자가 결정, G9·G10·G11 |
| 레벨별 배분 | 1번: G1·G2·G3, 보통 속도, 약 120 BPM / 2번: + G4·G5·G12, 약 128 BPM / 3번: + G6·G8, 약 140 BPM, 후반 빠름 | - |
| 시스템 | 진행도 % 바, 시도 횟수, 레벨별 최고 기록 저장(localStorage), 연습 모드(체크포인트), 일시정지, 오디오 오프셋 보정 | 수집품 3개(2차), 외형 해금, 업적, 계정·클라우드 저장 |
| 음악 | 자체 제작 또는 라이선스 명확한 곡 3개 | - |
| 성공 기준 (자동 플레이·지표) | 콘솔 에러 0, 사망→재시작 ≤ 0.8 s, 60/120 Hz에서 같은 입력 = 같은 궤적, 오디오-위치 오차 ≤ 20 ms(보정 후), 1번 레벨 평균 클리어 시도 3~15회 목표 | - |
