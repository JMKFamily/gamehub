# 20. 밸런스 설계: runner-01

- 입력: `00-benchmark.md` (감각 수치, MVP 범위), `10-lore.md` (레벨 이름·테마·튜토리얼 키), `30-art.md` (그림 크기, 화면 구성, 사운드). 1-2 교차 리뷰 반영 내용은 12장, 충돌 목록은 `reviews/cross/balance-designer.md`.
- 산출물
  - `balance.json`: 빌드가 그대로 읽는 수치 (모두 타일 단위, 키 이름에 단위 표기)
  - `levels/01-level1.json`, `levels/02-level2.json`, `levels/03-level3.json`: 레벨 데이터 (6장 스키마)
  - `tools/verify-levels.mjs`: 클리어 가능성·타이밍 창 검증기 (빌드·리뷰 재사용). 같은 물리를 `import`해서 쓸 수 있게 함수도 export
  - `tools/build-levels.mjs`: 레벨 설계 원본. 박자 단위로 기믹을 적으면 궤적을 계산해 타일 좌표 JSON을 만듦. 기존 JSON의 `name`/`theme_id`는 보존
- 레벨 배치는 원작 레벨을 옮긴 것이 아니라 아래 규칙으로 새로 설계했습니다 (원본 보호 규칙).

---

## 1. 설계 의도

1. **박자 = 탭.** 모든 탭이 정박 또는 반박에 오도록 장애물 x를 점프 궤적으로 역산했습니다. 검증기에서 "모든 탭을 박자에 맞춰 치는 입력열"이 세 레벨 모두 클리어됩니다 (9장).
2. **억울한 죽음 0.** 즉사 판정은 겉모양보다 항상 작고, 레벨별 최소 타이밍 창을 정해 검증기가 강제합니다 (1번 60 ms, 2번 40 ms, 3번 35 ms 이상).
3. **톱니형 난이도.** 구간마다 새 기믹은 "안전한 첫 등장 → 단독 연습 → 조합" 순서이고, 어려운 구간 뒤에는 2~4박 숨 고르기가 있습니다.
4. **첫 30초 = 튜토리얼.** 1번 레벨은 첫 탭이 4초, 첫 10초 동안은 4박(2초) 간격 단일 장애물 3개뿐입니다(창 238 ms). 30초 안에 탭 점프, 낮은 장애물, 블록 올라타기·계단·내려오기를 한 번씩 경험합니다.

## 2. 단위와 좌표계

| 항목 | 약속 |
|---|---|
| 길이 | 1타일(t) = 플레이어 몸체 한 변. 화면 픽셀 변환은 빌드가 함. `tile_px_reference: 48`(세로 10타일 = 480 px 기준)은 참고값 |
| 좌표 | x 오른쪽 +, **y 위쪽 +**, 바닥 윗면 y = 0. 바닥은 레벨 전체에 깔려 있음 (구덩이 없음) |
| 플레이어 위치 | (x, y) = 몸체 박스의 **왼쪽 아래**. 박스는 [x, x+1] × [y, y+1] |
| 오브젝트 위치 | (x, y) = 오브젝트가 차지하는 칸의 **왼쪽 아래**. x는 소수 허용(0.01 t 단위), y는 칸 행 |
| 시간 | 게임 시간 0 = 플레이어 x = 0 = 곡의 첫 박. 곡 파일에서 첫 박이 나오는 위치는 `audio_first_beat_s`로 맞춤 |

## 4. 물리·판정 규칙 (빌드가 그대로 구현할 것)

틱 길이 dt = 1/240 s. 매 틱 아래 순서로 처리합니다. `tools/verify-levels.mjs`의 `step()`이 기준 구현입니다.

1. **수평 이동**: x += speed × dt. speed는 입력과 무관합니다. 속도 변경 지점은 플레이어 중심(x + 0.5)이 지점의 x 이상이 된 틱부터 적용합니다. 속도 게이트 그림(1×3)은 가로 중심선이 이 x에 오도록 칸 왼쪽을 x − 0.5에 그립니다.
2. **입력**
   - 이번 틱에 *새로 눌렸고* 몸체 박스가 아직 안 쓴 공중 재점프 트리거와 겹치면: vy = `orb_velocity_t_s`, 그 트리거는 사용됨 (한 번만).
   - 아니면, 접지 상태이고 버튼이 *눌려 있으면*(탭이든 홀드든): vy = `jump_velocity_t_s`.
3. **적분**: vy' = max(vy − g·dt, −max_fall), y' = y + (vy + vy')/2 · dt (등가속 정확해. 오일러를 쓰면 최고점이 0.045 t 낮아져 레벨 여유가 달라지므로 금지).
4. **착지**: vy' ≤ 0이고, 고체(블록·얇은 발판)와 몸체 박스가 겹치며, y' ≥ 윗면 − `landing_snap_t`이면 y' = 윗면, vy' = 0, 접지. 여러 개면 가장 높은 윗면. y' ≤ 0이면 바닥에 착지. 받침이 없으면 접지가 풀리고 떨어집니다(코요테 타임 없음).
5. **발판형 자동 점프**: 몸체 박스가 안 쓴 발판 트리거와 겹치면 vy' = `pad_velocity_t_s` (입력 불필요, 한 번만).
6. **사망**: 즉사 장애물 판정 박스와 **몸체 박스**가 겹치거나, 블록과 **안쪽 박스**(중앙 0.3 × 0.3)가 겹치면 사망. 얇은 발판은 사망 판정 없음. 겹침은 경계가 닿는 것은 제외(열린 구간).
7. **클리어**: x ≥ `length_tiles`.

결정론: 같은 탭 시각 목록이면 같은 결과가 나와야 합니다. 입력 이벤트의 `timeStamp`를 게임 시간으로 바꿔 해당 틱에 반영합니다 (벤치마크 9장).

## 7. 레벨별 설계

### 레벨 1. 새벽 조율장 (`01-level1.json`, theme_id `level1`)

- 120 BPM, 보통 속도 고정, 96박 = **48.0 s**, 499.2 t. 오브젝트 47개 (spike 34, spike_low 7, block 6)
- 기믹: G1 블록, G2 바닥 장애물, G3 낮은 장애물. 1박 = 5.2 t

| 박 | 구간 | 내용 |

## 9. 클리어 가능성 검증

실행: `node tools/verify-levels.mjs` (옵션 `--json`, `--inputs`, 파일 경로 지정 가능). 레벨을 고쳤으면 `node tools/build-levels.mjs && node tools/verify-levels.mjs`.

검사 방법

1. 4장 규칙을 240 Hz로 시뮬레이션하면서, 틱마다 "탭한다 / 안 한다"를 너비 우선으로 펼쳐(같은 상태는 합침) 끝까지 사는 입력열을 찾습니다. 없으면 FAIL.

| 플레이어 | 팔각형 1×1 (모서리 0.2 잘림) | 1.0 × 1.0, 안쪽 0.3 × 0.3 | 30-art 4-1 설명과 같음 | 유지 |
| 속도 게이트 | 1×3 캡슐 | 판정 없음, 플레이어 중심이 `speed_changes.x`를 넘는 틱 | 그림 가로 중심 = x (4장 1번) | 그리기 위치 명시 |

### 12-2. 화면 높이 예산

30-art 5절: 세로 10타일, 바닥 윗면은 화면 아래에서 2타일, HUD는 위쪽 1.2타일 띠. 따라서 바닥 위로 **플레이어 머리 ≤ 6.8 t**면 세로 카메라를 고정해도 플레이어가 화면 밖이나 HUD 아래로 가지 않습니다 (`derived_reference.screen_head_budget_t`).

- 초안 레벨 3의 66박 높이 5 발판 위 점프는 머리 8.15 t로 화면 밖이었습니다. 발판을 높이 4로 낮추고 그 위 장애물을 없애, 박자대로 친 입력열 기준 최대 머리 높이는 1 / 2 / 3번 레벨 4.15 / 6.15 / 6.46 t입니다.
- 높이 4 발판 위에서 실수로 탭하면 머리가 7.15 t까지 올라가 HUD 띠에 0.35 t 걸리지만 판정에는 영향이 없습니다.
- 앞으로 레벨을 만들 때 규칙: 윗면 높이 + 2.15 + 1 ≤ 6.8 이 아닌 발판·블록 위에는 탭이 필요한 장애물을 두지 않습니다.
