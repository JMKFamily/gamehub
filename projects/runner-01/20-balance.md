# 20. 밸런스 설계: runner-01

- 입력: `00-benchmark.md` (감각 수치, MVP 범위). 세계관·아트 문서는 병렬 작업 중이라 레벨 이름/테마는 자리표시자(`theme_id: "level1"` 등, `name: null`)로 두고 1.5단계 교차 리뷰에서 채웁니다.
- 산출물
  - `balance.json`: 빌드가 그대로 읽는 수치 (모두 타일 단위, 키 이름에 단위 표기)
  - `levels/01-level1.json`, `levels/02-level2.json`, `levels/03-level3.json`: 레벨 데이터 (6장 스키마)
  - `tools/verify-levels.mjs`: 클리어 가능성·타이밍 창 검증기 (빌드·리뷰 재사용). 같은 물리를 `import`해서 쓸 수 있게 함수도 export
  - `tools/build-levels.mjs`: 레벨 설계 원본. 박자 단위로 기믹을 적으면 궤적을 계산해 타일 좌표 JSON을 만듦. 기존 JSON의 `name`/`theme_id`는 보존
- 레벨 배치는 원작 레벨을 옮긴 것이 아니라 아래 규칙으로 새로 설계했습니다 (원본 보호 규칙).

---

## 1. 설계 의도

1. **박자 = 탭.** 모든 탭이 정박 또는 반박에 오도록 장애물 x를 점프 궤적으로 역산했습니다. 검증기에서 "모든 탭을 박자에 맞춰 치는 입력열"이 세 레벨 모두 클리어됩니다 (9장).
2. **억울한 죽음 0.** 즉사 판정은 겉모양보다 항상 작고, 레벨별 최소 타이밍 창을 정해 검증기가 강제합니다 (1번 60 ms, 2번 40 ms, 3번 35 ms 이상).
3. **톱니형 난이도.** 구간마다 새 기믹은 "안전한 첫 등장 → 단독 연습 → 조합" 순서이고, 어려운 구간 뒤에는 2~4박 숨 고르기가 있습니다.
4. **첫 30초 = 튜토리얼.** 1번 레벨은 첫 탭이 4초, 첫 10초 동안은 4박(2초) 간격 단일 장애물 3개뿐입니다(창 238 ms). 30초 안에 탭 점프, 낮은 장애물, 블록 올라타기·계단·내려오기를 한 번씩 경험합니다.

## 2. 단위와 좌표계

| 항목 | 약속 |
|---|---|
| 길이 | 1타일(t) = 플레이어 몸체 한 변. 화면 픽셀 변환은 빌드가 함. `tile_px_reference: 48`(세로 10타일 = 480 px 기준)은 참고값 |
| 좌표 | x 오른쪽 +, **y 위쪽 +**, 바닥 윗면 y = 0. 바닥은 레벨 전체에 깔려 있음 (구덩이 없음) |
| 플레이어 위치 | (x, y) = 몸체 박스의 **왼쪽 아래**. 박스는 [x, x+1] × [y, y+1] |
| 오브젝트 위치 | (x, y) = 오브젝트가 차지하는 칸의 **왼쪽 아래**. x는 소수 허용(0.01 t 단위), y는 칸 행 |
| 시간 | 게임 시간 0 = 플레이어 x = 0 = 곡의 첫 박. 곡 파일에서 첫 박이 나오는 위치는 `audio_first_beat_s`로 맞춤 |

## 4. 물리·판정 규칙 (빌드가 그대로 구현할 것)

틱 길이 dt = 1/240 s. 매 틱 아래 순서로 처리합니다. `tools/verify-levels.mjs`의 `step()`이 기준 구현입니다.

1. **수평 이동**: x += speed × dt. speed는 입력과 무관합니다. 속도 변경 지점은 플레이어 중심(x + 0.5)이 지점의 x 이상이 된 틱부터 적용합니다.
2. **입력**
   - 이번 틱에 *새로 눌렸고* 몸체 박스가 아직 안 쓴 공중 재점프 트리거와 겹치면: vy = `orb_velocity_t_s`, 그 트리거는 사용됨 (한 번만).
   - 아니면, 접지 상태이고 버튼이 *눌려 있으면*(탭이든 홀드든): vy = `jump_velocity_t_s`.
3. **적분**: vy' = max(vy − g·dt, −max_fall), y' = y + (vy + vy')/2 · dt (등가속 정확해. 오일러를 쓰면 최고점이 0.045 t 낮아져 레벨 여유가 달라지므로 금지).
4. **착지**: vy' ≤ 0이고, 고체(블록·얇은 발판)와 몸체 박스가 겹치며, y' ≥ 윗면 − `landing_snap_t`이면 y' = 윗면, vy' = 0, 접지. 여러 개면 가장 높은 윗면. y' ≤ 0이면 바닥에 착지. 받침이 없으면 접지가 풀리고 떨어집니다(코요테 타임 없음).
5. **발판형 자동 점프**: 몸체 박스가 안 쓴 발판 트리거와 겹치면 vy' = `pad_velocity_t_s` (입력 불필요, 한 번만).
6. **사망**: 즉사 장애물 판정 박스와 **몸체 박스**가 겹치거나, 블록과 **안쪽 박스**(중앙 0.3 × 0.3)가 겹치면 사망. 얇은 발판은 사망 판정 없음. 겹침은 경계가 닿는 것은 제외(열린 구간).
7. **클리어**: x ≥ `length_tiles`.

결정론: 같은 탭 시각 목록이면 같은 결과가 나와야 합니다. 입력 이벤트의 `timeStamp`를 게임 시간으로 바꿔 해당 틱에 반영합니다 (벤치마크 9장).

## 5. 장애물 배치 규칙

| 규칙 | 값 | 이유 |
|---|---|---|
| 따로 치는 장애물 사이 최소 간격 | 1박 | 120/128/140 BPM 1박(0.50/0.47/0.43 s)은 모두 체공 0.40 s보다 길어 착지 후 다음 박에 탭 가능. 1박 연속은 단일·2연속까지만 |
| 3연속 장애물 | 앞 1박을 비움 | 3연속 창이 46 ms라 직전 착지가 늦으면 창이 더 줄어듦 (3번 레벨 초안에서 29 ms로 측정돼 수정) |
| 연속 개수 상한 (지면 점프 1회) | 보통 3, 느림 2, 빠름 3 | 3장 파생값 |
| 공중 재점프 1회 포함 | 보통 5~6, 느림 3 | 지면 점프 + 반박 뒤 재점프 궤적으로 계산 |
| 발판 자동 점프 | 바닥 장애물 3연속까지 넘김, 높이 3 블록·발판까지 | 최고 3.39 t |
| 블록·발판 끝 | 마지막 박 위치 + 0.8 t | 끝 박에 그 위에서 점프해도 떨어지지 않게 |
| 천장 장애물 | 바닥 위 행 2 (지면에서 뛰면 사망), 블록 위 행 3, 높이 2 발판 위 행 4 | "뛰지 말아야 할 때". 걸어 지나가면 항상 안전 |
| 새 기믹 첫 등장 | 실패해도 아무 일 없는 배치 | 발판: 장애물 없이 단독 / 천장: 아래를 걸어가기만 / 공중 재점프: 단일 장애물 위에 띄워 눌러도 안 눌러도 생존 |
| 박자 정렬 | 지면 탭은 정박(일부 반박), 공중 재점프는 반박 | 생성기가 궤적의 "판정 높이 위 구간" 가운데에 장애물을 놓아 탭 창 중심 = 박 |

## 6. 레벨 데이터 스키마 (`levels/*.json`, schema_version 1)

빌드는 `balance.json`의 `levels` 배열 순서대로 파일을 읽습니다. 파일 이름의 `level1` 부분은 이름 확정 후 바꿔도 되며, 그때 `levels` 배열도 같이 바꿉니다.

| 필드 | 타입 | 뜻 |
|---|---|---|
| `schema_version` | 1 | 스키마 버전 |
| `id` | "01" | 레벨 번호 (진행 순서, 저장 키) |
| `theme_id` | "level1" | 아트·음악·배경 테마 연결 키. 자리표시자, 교차 리뷰에서 확정 |
| `name` | string \| null | 표시 이름. 세계관 작가가 채움 |
| `bpm` | number | 곡 BPM (박자 연출, 오디오 동기화) |
| `beats_per_bar` | 4 | 마디당 박 (배경 펄스 강박 위치) |
| `audio_first_beat_s` | number | 곡 파일에서 첫 박(게임 시간 0)이 나오는 초. 곡 확정 후 빌드가 맞춤 |
| `start_speed` | "slow" \| "normal" \| "fast" \| "very_fast" | 시작 속도 단계 (`balance.json speeds_t_s` 키) |
| `player_start` | {x, y} | 시작 위치 (현재 모두 0, 0) |
| `length_beats` | number | 레벨 길이 (박) |
| `length_tiles` | number | 결승선 x. 플레이어 x가 이 값 이상이면 클리어. 진행도 % = x / length_tiles |
| `duration_s` | number | 클리어까지 걸리는 시간 = 곡에서 써야 할 길이 (곡은 이보다 2~3초 길게) |
| `difficulty` | {stars, expected_attempts[min,max], first_try_reach_pct, clear_rate_10_tries} | 목표 지표 (자동 플레이·리뷰 비교용, 게임 로직은 안 씀) |
| `design_intent` | string | 설계 메모 (표시 안 함) |
| `speed_changes` | [{x, speed, beat}] | 속도 변경 지점. 4장 1번 규칙으로 적용. `beat`는 참고값 |
| `sections` | [{name, start_beat, x, intensity}] | 구간. 연출 전용(G13): intensity 0~4로 배경 펄스 세기·색 전환. 판정 없음 |
| `objects` | [오브젝트] | 아래 표. x 오름차순 정렬 |

오브젝트 (`x`, `y`는 칸 왼쪽 아래, 타일 단위)

| `type` | 추가 필드 | 차지 영역 / 판정 | 벤치마크 코드 |
|---|---|---|---|
| `block` | `w`, `h` (기본 1) | 고체 [x, x+w] × [y, y+h]. 윗면 착지, 안쪽 박스 닿으면 사망. 현재 모두 y = 0인 기둥 | G1 |
| `platform` | `w` | 얇은 발판. 칸 윗부분 [y+0.75, y+1]. 윗면 = y+1 | G12 |
| `spike` | - | 겉모양 칸 [x, x+1] × [y, y+1]. 판정 [x+0.375, x+0.625] × [y, y+0.45]. y = 놓인 면 높이 | G2 |
| `spike_low` | - | 겉모양 높이 0.5. 판정 [x+0.375, x+0.625] × [y, y+0.2] | G3 |
| `spike_ceiling` | - | 칸 윗변에 매달림. 판정 [x+0.375, x+0.625] × [y+0.55, y+1] | G4 |
| `pad` | - | 놓인 면 위. 트리거 [x+0.1, x+0.9] × [y, y+0.25] | G5 |
| `orb` | - | 칸 중심 기준 1.2 × 1.2 트리거 | G6 |

연속 장애물은 칸마다 한 개씩 적습니다(묶음 표기 없음). 중력 반전(G7)과 MVP 제외 기믹은 스키마에 없습니다.

아트 쪽 에셋 이름(`hazard-floor`, `hazard-floor-low`, `hazard-ceiling`, `jump-pad`, `air-orb`, `thin-platform`, `block`, `gate-speed-*`)과의 대응은 교차 리뷰에서 확정합니다. 스키마의 `type` 값은 기능 이름이라 바꾸지 않는 것을 권장합니다.

## 9. 클리어 가능성 검증

실행: `node tools/verify-levels.mjs` (옵션 `--json`, `--inputs`, 파일 경로 지정 가능). 레벨을 고쳤으면 `node tools/build-levels.mjs && node tools/verify-levels.mjs`.

검사 방법

1. 4장 규칙을 240 Hz로 시뮬레이션하면서, 틱마다 "탭한다 / 안 한다"를 너비 우선으로 펼쳐(같은 상태는 합침) 끝까지 사는 입력열을 찾습니다. 없으면 FAIL.
2. 찾은 탭을 정박(안 되면 반박)으로 옮기고, 탭마다 앞뒤로 몇 ms까지 어긋나도 클리어되는지(나머지 탭은 고정) 잽니다. 최소 창이 `verify_min_window_ms` 미만이면 FAIL.
3. 모든 탭을 박자에 맞춘 입력열이 클리어되지 않으면 FAIL.
4. 무입력 또는 계속 누르기만으로 클리어되면 FAIL.

## 11. 교차 리뷰·빌드에 넘길 것

- 세계관 작가: `name`, `theme_id` 확정 (생성기를 다시 돌려도 보존됨). 파일 이름 변경 시 `balance.json levels`도 수정.
- 아티스트: 오브젝트 `type` ↔ 에셋 대응. 겉모양은 판정보다 커야 함(판정 > 겉모양 금지). 낮은 장애물 겉모양 높이 0.5 t.
- 작곡·빌드: 곡 길이 ≥ `duration_s` + 2 s, 첫 박을 `audio_first_beat_s`에 기록. 연출은 `sections.intensity`와 `beats_per_bar` 사용.
- 빌드: 4장 틱 순서를 그대로 구현하고, 자동 플레이 검사는 `verify-levels.mjs --json --inputs`의 탭 시각을 재생해 클리어 여부를 비교하면 물리 일치 여부까지 확인됩니다.
