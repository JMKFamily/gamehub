## 요청 받은 일
오케스트레이터가 요청자 추가 지시(2026-11-17, 전 프로젝트) "판정 이름과 퍼센트까지 해주세요."를 전달했습니다. 앞서 권장한 "글 없이 등급 구분"을 바꿔, 탭마다 판정 이름과 DJMAX식 퍼센트를 보여 주는 공통 권장안을 `harness/benchmarks/djmax-judgement.md`에 새 절로 쓰는 일입니다.

## 한 일
1. 원작 퍼센트 구조를 웹으로 조사했습니다(앱 조작·실측 없음).
   - 성공 11단계(100 %, 90~10 %, 1 %)와 BREAK, 100 % 폭 ±41.6 ms 추정, 판정률 = 단순 평균, 점수 = 정확도 × 10,000을 확인했습니다.
   - 단계별 ms와 표시 크기·지속 시간은 공개 자료가 없어 "미확인"으로 남겼습니다.
2. |Δ| → % 계단식 공통 계산식을 만들었습니다. 기존 등급 경계(±50 / g / 통과 창 끝 W)에 맞췄고, 정규분포 계산으로 창 끝 값과 σ25·σ70 정확도 분포를 확인했습니다.
3. 레벨 정확도 규칙을 정했습니다. 클리어 시도의 평균을 정수로 내리고, 실패·연습 시도는 정확도를 내지 않습니다.
4. 자체 판정 이름 3개(KR/EN), 가독 크기, 표시 시간, 바꿔 그리기 규칙을 정했습니다. runner-01의 최소 판정 간격 178.6 ms를 새로 계산해 반영했습니다.
5. 세 게임의 이름·% 자리와 결과 화면 메모를 7-6절에 적었습니다.
6. 기존 절에서 이 지시로 바뀐 문장 9곳을 고치고 "(2026-11-17 요청자 추가 지시로 변경)"을 붙였습니다.
   - 대상: 머리말, 0절 표·설명 2줄, 4-1 표 머리·설명, 4-3 숫자 줄, 4-4 클리어 줄, 5-2, 5-3
7. 출처 S14~S16을 더하고 `harness/insights.md` 레퍼런스 감각 절 맨 아래에 2줄을 덧붙였습니다.

### 계산식 요약
d = |탭 − 설계 박|, g = 좋아 경계(100, rhythm L4부터 90), W = Δ 쪽 통과 창 끝.

| d 범위 | % | 등급 |
|---|---|---|
| ≤ 25 | 100 | 딱 |
| ≤ 50 | 90 | 딱 |
| ≤ g (3칸) | 80 / 70 / 60 | 좋아 |
| ≤ W (5칸) | 50 / 40 / 30 / 20 / 10 | 통과 |
| > W | 표시 없음 | 실패 |

- 창 끝은 언제나 10 %입니다. runner-01에서 창이 100 ms 이하인 탭은 60·70 %가 최저입니다.
- %만 보고도 등급을 알 수 있습니다: 90 이상은 딱, 60~80은 좋아, 10~50은 통과.

### 이름 권장
| 등급 | 한국어 | 영어 |
|---|---|---|
| 딱 | 딱이야 | Wow! |
| 좋아 | 좋아 | Nice |
| 통과 | 됐어 | OK |

- 실패 칸에는 이름을 만들지 않습니다. 최종 문구는 lore-writer가 정합니다.

## 검증 결과
- 계산식 정규분포 계산(scratchpad `pct.mjs`, 클리어 시도 3000회)
  - 창 끝 값: 모든 경우 10 %(창 ≤ 100 ms이면 60·70 %)
  - 경계: 50 ms → 90, 51 ms → 80, g ms → 60, g+1 ms → 50
  - 레벨 정확도 중앙값: σ25 96 %, σ70 80~81 %. runner 좁은 창만 있는 가정에서는 σ70 88 %
- runner-01 `levels/*.json judge_taps` 읽기 전용 계산
  - 탭별 창: 이른 쪽 80.8~250 ms, 늦은 쪽 82.4~245.9 ms
  - 최소 판정 간격: L1~5 810.8~1000 ms, L6~10 178.6~197.3 ms
- 하지 않은 것
  - 실제 레벨·헛탭을 넣은 봇 재측정은 하지 않았습니다(balance 몫).
  - 원작 영상 프레임 측정은 하지 않았습니다(실측 금지 범위).

## 규칙 준수 확인
- [x] 원본 보호: MAX·BREAK 등 원작 이름, "MAX n%" 표기, 글자 디자인·폰트·소리를 쓰지 않았습니다. 구조와 계산 방식만 가져왔습니다.
- [x] 게임 선정·설계 원칙

  - %는 이름보다 작게 표시합니다.
  - 클리어·실패·30회 한도는 바뀌지 않습니다.
- [x] 결제·광고 클릭·계정 변경 없음, 웹 조사만 했습니다.
- [x] 담당 파일만 수정했고 git 작업은 하지 않았습니다. 게임 코드와 다른 팀 폴더는 읽기만 했습니다.
  - 공유 scratchpad에서 계산용 `pct.mjs`·`ed.mjs`를 `cat >`/새로 쓰기로 만들었습니다. 같은 이름의 다른 세션 파일이 있었다면 덮였을 수 있습니다(내용 확인 불가).

## 다른 팀에 줄 인사이트
- 판정 %는 등급과 같은 Δ 하나로 계산하는 계단 함수로 만들면 등급과 숫자가 어긋나지 않습니다. 실패한 시도의 정확도는 내지 않아야 "일찍 죽을수록 높은 %" 같은 왜곡이 없습니다. insights.md에 반영했습니다.
