## 요청 받은 일
요청자 지시(2026-11-17): "Geometry Dash 벤치마킹은 계속 진행합니다. 얻은 인사이트는 모든 개발팀에 전달해야 해요." 오케스트레이터가 두 가지를 맡겼습니다.
- A. runner-01에서 얻은, 다른 프로젝트(rhythm-01, rhythm-02 등)에도 쓸 수 있는 인사이트를 `harness/insights.md` 각 절에 채우기. GD 자체에서 배울 점은 "레퍼런스 감각" 절에 따로.
- B. 레벨 4~10 새 기믹(현 발판, 템포 문 빠름/느림, 울림 고리, 천장 가시)과 연습 모드·진행도 표시가 레퍼런스와 감각적으로 맞는지 판단할 자료가 부족한 곳을 찾고, 공개 자료로 정리하고, 필요하면 블루스택에서 안전 수칙대로 실측.

1. 규칙 문서(에이전트 정의, CLAUDE.md, PIPELINE, criteria, insights, 실측 가이드, STATUS)와 근거 자료(00-benchmark, measurements, Docs 아래 보고서 전부, reviews/round-1)를 읽었습니다.
2. **A. `harness/insights.md`에 44줄을 넣었습니다.** 형식은 "규칙" 절대로 `- [runner-01·2026-11-17] 인사이트. 근거: 경로. 적용: 역할`입니다. 작업 중 rhythm-01·rhythm-02 팀이 같은 파일에 먼저 줄을 넣어 둔 것을 확인해, 우리 줄을 각 절 **맨 아래**로 옮겼고 남의 줄은 고치지 않았습니다. 겹치는 2줄(연속 중앙값, 시작 직후 1% low)은 "위 rhythm-01 항목 채택/같은 현상, 수정 결과"로 바꿔 중복을 피했습니다. runner-01에만 해당하는 수치(블록 크기, 레벨 이름 등)는 근거로만 쓰고 인사이트 문장에는 넣지 않았습니다.
3. **B. 기믹·시스템 대응 점검**: 레벨 4~10 기믹마다 레퍼런스 대응 기능, 공개 자료로 확인된 것, 판단 자료가 부족한 것을 표로 정리해 `00-benchmark.md` 12절(새 절, 기존 절은 수정 안 함)에 넣었습니다.
4. **B. 실측(블루스택, adb 127.0.0.1:6610)**: 에뮬레이터와 게임이 켜져 있어 연습 모드·진행도 표시만 측정했습니다. 플레이 중 입력은 0회, 결과 화면 재시작 버튼 탭 2회만 `seq.sh`(포커스 가드)로 보냈습니다. 분석 도구 `benchmark/tools/burst-intervals.mjs`를 새로 만들었습니다.
5. 측정 결과를 `benchmark/measurements.md`에 "round-2 추가 실측" 절로 덧붙이고 근거 프레임 3장을 저장했습니다.
6. 광고 닫기 중 사고 1건이 있어 측정을 그 자리에서 멈췄습니다(아래 "규칙 준수 확인").

## 검증 결과
- `node tools/burst-intervals.mjs raw/r2p2.mp4` → 사망 폭발 42회, 간격 41개 1.067 ± 0.011 s (1.048~1.084). 80연속 프레임 타일에서 부활 후 1~2프레임 뒤 폭발이 시작되는 것을 눈으로 확인했습니다.
- 진행도 막대 없음: 이번 영상 2개와 1차 실측 프레임(`frames/sc3_03_*`) 모두 상단에 막대가 없습니다. 설정 화면은 열지 않았습니다(설정 변경 금지).
- 우리 빌드 확인: `games/reverbound/js/main.js`(`cpPlace`·`cpRemove`, `pRestart`가 체크포인트를 지움, `practiceAttempts`), `games/reverbound/js/game.js`(`placeCheckpoint` 수동만, 자동 체크포인트 코드 없음), `games/reverbound/js/physics.js`(`platform`은 위에서만 밟힘, 고리는 새로 누를 때만 발동), `balance.json`(천장 0.25 × 0.45). 읽기만 했습니다.
- `insights.md`: 줄 수 44, 각 절에서 다른 팀 줄 아래에 놓였는지 확인했습니다. 작업 전 백업과 비교해 남의 줄은 바뀌지 않았습니다.
- 공개 자료: GD 위키 본문은 402로 접속이 막혀 검색 결과 요약만 확인했습니다. 발판·고리 높이 수치를 준 공개 자료는 찾지 못했습니다.
- Windows Git Bash에서 `adb pull /sdcard/…`가 경로 변환으로 실패해 `MSYS_NO_PATHCONV=1`로 해결했습니다 (실측 안전 절 인사이트로 넣음).
- 못 한 것: 발판·고리·천장·얇은 판·속도 문 실측(n=0). 이유는 1차 실측과 같습니다. 화면을 보지 않는 자동 입력으로는 첫 레벨 3 %를 넘지 못하고, 해당 기믹은 둘째 레벨 이후에 있습니다. 소리는 `screenrecord`가 녹음하지 않습니다.

## 다른 팀에 줄 인사이트
`harness/insights.md`에 바로 넣었습니다(요청 범위). 오케스트레이터가 다른 팀 세션에 알릴 핵심:
1. 재시작은 "즉시"가 아니라 약 1초 박자(레퍼런스 1.11 s)입니다. 측정 정의는 "사망 틱 → 다음 시도 첫 프레임"으로 통일합니다.
2. 첫 레벨은 아동 대리 봇(σ70)으로 먼저 맞춥니다. 초반 레벨이 가파르면 레벨 10 외삽이 무너집니다(347회 → 6회로 고친 뒤에야 곡선이 섬).
3. 연속 장애물은 비용이 약 3배라 새 기믹처럼 예산으로 묶습니다. 몰림은 가장 좁은 탭을 여러 곳에 나눠 낮춥니다. 숙련 봇 표본은 10만 회 단위가 필요합니다.
4. 화면 문구는 12자, 모양 이름으로 씁니다. 테스트 훅 화면 = 일반 모드(UI 시계 = 게임 시간)이고, 첫 프레임 튐은 미리 그리기로 없앱니다.
5. 실측 안전: 포커스 가드로만 입력합니다. 광고는 ✕만 누릅니다(▷|가 스토어 창을 연 사고).
