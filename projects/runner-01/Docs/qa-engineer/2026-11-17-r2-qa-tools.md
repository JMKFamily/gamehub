# round-2 QA 도구 준비 (10레벨 대응, 밸런스 자동 측정, 영어 화면)

- 날짜: 2026-11-17
- 역할: qa-engineer
- 프로젝트: runner-01 (slug `reverbound`)
- 단계: round-2 (QA 도구 준비, 정식 round-2 QA 전)

## 요청 받은 일
오케스트레이터가 QA 도구 준비만 요청했습니다. 요청자 지시로 레벨이 10개가 됐고(빌드 485370f), 개발 보고서 `Docs/game-developer/2026-11-17-r2-build.md`의 qa 인계에 따라 다음을 합니다. 아트 담당이 레벨 4~10 확정값을 쓰는 중이라 정식 round-2 QA와 채점은 나중에 따로 합니다.
1. 레벨 수 하드코딩을 없애고 10레벨을 모두 돌게 하기
2. criteria 밸런스 새 항목 2개를 자동으로 재는 파트 추가
3. 영어 화면(lang=en) 스크린샷 파트 확인, 없으면 추가
4. `--quick`으로 한 번 돌려 오류 없이 도는지만 확인 (점수 없음)

## 한 일
1. **레벨 목록을 빌드에서 읽기** (`qa-round.mjs`)
   - 시작할 때 페이지를 한 번 열어 `__game.levelCount`, `levelData(i)`(id·길이·오브젝트 수·bpm)를 읽습니다.
   - `games/reverbound/data/balance.json`의 `levels`와 대조해 `parts/levels.json`에 남깁니다. 다르면 경고를 띄웁니다.
   - `['01','02','03']` 고정과 `for i < 3` 반복을 모두 없앴습니다. 대상 파트는 shots·replay·bots·realtime·features(저장·연습 키)입니다.
   - perf의 "오브젝트 최다 레벨"을 레벨 3 고정에서 데이터 기준 선택으로 바꿨습니다(지금은 레벨 07, 235개).
   - 레벨별 플레이 스크린샷은 시간 고정값 대신 새 훅 `seek(i, x)`로 레벨 길이 35 % 지점에서 찍습니다. 마지막 레벨 클리어 화면 샷도 추가했습니다.
   - features에 레벨 선택 카드 수 = `levelCount` 확인(`level_cards`)을 추가했습니다.
2. **`balance` 파트 추가** (node 전용, 이 파트만 돌리면 브라우저·서버를 띄우지 않음)
   - `tools/sim/bots.mjs`를 레벨별 자식 프로세스로 병렬 실행합니다(`--jobs`, 기본 CPU−1). bots.mjs는 수정하지 않았습니다.
   - σ70: `bots.mjs <bal-n> child_sd70 <id> <bal-sessions>`. 5번째 인자로 세션 시뮬레이션을 돌립니다.
   - σ25: `bots.mjs <bal-skilled-n> skilled_sd25 <id> 0`.
   - 기본 표본: σ70 20000회 + 1000세션, σ25 100000회(balance 보고 기준). quick은 300 / 20 / 300입니다.
   - **B30**: 모든 레벨의 σ70 첫 클리어 중앙값이 30회 이하인지, 직전 레벨의 2배 이하인지 봅니다.
   - **B10**: 레벨 1·3 중앙값으로 기하 평균 배율 g = √(m3/m1)을 구하고, 외삽 레벨 6 = m3·g³를 목표로 잡습니다. 레벨 10이 그 목표의 ±20 % 안인지, 레벨 3~10이 엄격 단조인지 봅니다.
   - 판정용 중앙값은 criteria R3을 따라 연속 중앙값 ln 0.5 / ln(1 − p)를 씁니다(p = 시뮬레이터 σ70 첫 시도 클리어율, 한 원천). 세션 중앙값과 정수 중앙값은 참고로 같이 적습니다.
   - **SK**: σ25 사망 몰림(6 t 창)이 30 % 이하인지 봅니다. σ25 사망이 20회 미만인 레벨은 σ50으로 다시 봅니다(rhythm-01 항목 준용).
   - bots.mjs는 프로세스마다 같은 시드(12345)로 시작합니다. 그래서 한 레벨을 여러 프로세스로 쪼개지 않습니다. 쪼개면 같은 난수열이 반복되어 표본이 커지지 않습니다.
3. **영어 화면**
   - 기존 도구는 basic에서 `?lang=en`을 열어 콘솔만 봤고, 영어 스크린샷은 없었습니다.
   - shots 파트를 `--langs`(기본 `ko,en`)마다 같은 세트로 찍게 했습니다. 파일 이름은 `ko-…`, `en-…`로 시작합니다. 글 넘침·HUD 잘림 검사도 언어마다 합니다.
   - age 파트의 버튼 크기 측정도 언어마다 합니다. 글 지운 화면은 언어와 무관해서 한 번만 찍습니다.
   - 빌드가 `navigator.language`로 언어를 자동 선택하게 바뀌어서, 모든 페이지에 `?lang=`를 명시해 결과가 언어에 따라 흔들리지 않게 했습니다.
   - basic에 언어 자동 선택 검사를 추가했습니다(locale ko-KR → ko, en-US → en, `lang_auto`).
4. **옵션 추가**: `--quick`, `--levels`, `--langs`, `--n`, `--bal-n`, `--bal-sessions`, `--bal-skilled-n`, `--jobs`, `--out-dir`
   - quick 결과는 `reviews/round-N-quick/`에 따로 씁니다. 정식 `round-2/` 폴더는 비어 있는 그대로 둡니다.
5. **round-1 때 맞던 고정값이 지금 빌드와 어긋난 곳 1건 수정**
   - features 연습 모드 검사가 사망 후 0.61 s만 기다렸는데, 지금 재시작 지연은 1.08 s입니다.
   - 그래서 빌드가 아니라 도구가 "체크포인트 재시작 실패"로 잘못 기록했습니다.
   - 대기 시간을 `balance.json`의 `restart_delay_s` + 0.05 s로 바꾸고, 판정을 여유 틱 안으로 고쳤습니다.
6. **`selfcheck-browser.mjs`**
   - 위치는 `projects/runner-01/tools/selfcheck-browser.mjs`입니다(개발 1-3 자체 확인 도구, 결과는 `reviews/dev-selfcheck/`).
   - 레벨 반복과 입력열 키를 `levelCount`·`levelData(i).id`로 바꿨습니다. 레벨별 장면은 `seek`로 찍고, 클리어 연출은 마지막 레벨로 찍습니다.

## 검증 결과
실행 환경: Windows, 설치된 Edge headless, playwright-core 1.48.2(`QA_CHANNEL=msedge`), QA 포트 8124. 서버는 도구가 띄우고 끝나면 종료합니다.

```
PLAYWRIGHT_CORE=<playwright-core 경로> QA_CHANNEL=msedge node projects/runner-01/tools/qa-round.mjs --round 2 --quick
node projects/runner-01/tools/qa-round.mjs --round 2 --quick --merge
```

- 9개 파트가 모두 종료 코드 0으로 끝났습니다. 총 5분 28초, balance 파트는 30.8 s입니다.
- 콘솔 에러·경고 0, 페이지 에러 0, 실패 요청 0, 외부 요청 0입니다(요청 1137건, 모두 localhost).
- 레벨 목록: 훅 10개 = data balance.json 10개(`count_match: true`). 10레벨 모두 테스트 입력열이 있습니다.
- 파트별 결과(quick 축소)

| 파트 | 결과 |
|---|---|
| shots | 186장, 그중 en 80장. 언어 확인 ko 4/4, en 4/4. 글 넘침·HUD 잘림 기록 0 |
| replay | 10레벨 × 2입력열 × 2홀드 × 2프레임 + 음성 대조 = 100회. 기대와 어긋난 결과 0 |
| bots | 4프로필 × 10레벨 × 20회, 레벨 1 세션 10회 |
| realtime | 10레벨 각 6 s 진행. 끝까지 가지 않아 상태는 playing |
| perf | 1280x720·640x360 DPR 3, 각 8 s. 재시작·반응 측정 동작 |
| features | 연습 체크포인트 재시작 true, 연습 클리어. 진행도 저장 유지, 카드 10 = levelCount |
| age | ko·en × 4해상도 버튼 측정 동작 |
| balance | 10레벨 B30·B10·SK 계산 동작 |
| basic | 언어 자동 선택 ko-KR → ko, en-US → en |

- **점수는 매기지 않았습니다.** quick 표본은 300회·20세션이라 판정에 쓸 수 없습니다.
  - 예: 레벨 09·10의 p가 0.013~0.017이면 사망이 4~5회뿐이라 연속 중앙값이 크게 흔들립니다.
  - 정식 round-2 QA에서 기본 표본(σ70 20000 + 1000세션, σ25 100000)으로 다시 잽니다.
  - quick에서 σ25 사망이 레벨마다 20회 미만이어서 10레벨 모두 σ50으로 대체되었습니다. 대체 경로가 동작하는 것도 확인했습니다.
- `selfcheck-browser.mjs`는 문법 검사(`node --check`)만 했습니다. 실행하면 개발 담당 폴더 `reviews/dev-selfcheck/`의 기존 결과를 덮어쓰기 때문입니다.
