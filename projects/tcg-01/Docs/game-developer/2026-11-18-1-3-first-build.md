## 요청 받은 일
오케스트레이터(요청자 지시 전달): 하스스톤 느낌 TCG(18세)의 첫 웹 빌드. 요청자 지시 "카드 결투 진행할 때 중요한 건 연출의 템포감과 몰입감" → 30-art 5절·`art.json tempo` 수치 그대로(첫 반응 ≤ 100 ms, 예약 3개·2배속, 강약 4단계, AI 턴 박자, 빠르게 보기, 턴 타이머, 대사·명줄 위기, Web Audio). 규칙 엔진은 시뮬레이터 파일을 수정 없이 복사·해시 기록. 메타(수집·공명·새김, 덱 빌더, 인양 상자, 시장, 각인 먹, 의뢰·달력) 최소 동작, 테스트 훅, DEV_NOTES.

3. 연출 틀(`js/anim.js`·`fx.js`): 게임 시계 트윈(transform/opacity만), 타임라인 잠금·예약(최대 3)·2배속·끝 상태로 넘기기, Canvas 한 장 효과(입자 예산 120/300).

5. 메타(`js/meta.js`·`screens.js`): 타이틀 → 부두 → 호명자 선택(6명, 표준 영장첩·내 영장첩, 모드 3종, 난이도 2단계) → 대전 → 결과·보상. 수집 200장(공명 막대·새김 돌파·단계별 돌파 수치·지정 새김), 영장첩 빌더(30장·2장·심해 1장·전용 규칙, 심지 곡선, 나머지 채우기), 인양 상자(확률·보장 칸·등대 보장·심해 중복 보호, 개봉 연출 5단계·모두 부수기), 부두 시장(게임 내 재화만), 의뢰 3칸(보상·다시 받기), 조수 달력, 설정(ko/en·소리·음악·빠르게 보기·움직임 줄이기·타이머). 저장 localStorage. 20-balance D1 모드별 돌파 규칙 반영(연습 전부/친선 1종/맹약 0단계).
6. 테스트 훅 `window.__game`(state, screen, battle, newBattle, mulligan, act, endTurn, legal, runAI, autoplay, step, tempoLog, log, export, save/load…)과 쿼리 `test=1`·`anim=0`·`manual=1`·`lang`.
7. `projects/tcg-01/DEV_NOTES.md`: 구조, 템포 구현, 기획과 다르게 한 점 D1~D10, 훅 사용법·QA 대조 방법.

## 다른 팀에 줄 인사이트
- 엔진이 모듈 전역 카운터(예: AI 앞보기 난수 SALT)를 가지면 "같은 시드 = 같은 판"이 프로세스·페이지 안 판 순서에 따라 깨진다. 브라우저는 `import('./ai.mjs?fresh=N')`로 판마다 새 모듈, node 대조는 판마다 새 프로세스로 맞추면 불일치 0이 된다(tcg-01 DEV_NOTES 테스트 훅 절).
- 연출을 "엔진 결과 확정 → 이벤트 로그 → 타임라인"으로 만들고 잠금 중 입력을 버리지 않고 예약하면, 연출을 건너뛰거나 2배속으로 감아도 최종 화면은 항상 엔진 상태와 같아 정보 손실이 없다.
